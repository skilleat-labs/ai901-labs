    Lab 08 — 포털에서 에이전트 만들기

    이 실습에서 하는 것

    어제 chat3.py 는 규정을 프롬프트에 직접 붙였습니다. 문서가 커지면 못 씁니다. 오늘은 문서를 업로드해서 붙이는 에이전트를 만듭니다.

    선행 Lab 07 완료 · 예상 시간 40분 · 비용 약 $0.05 미만

    0. 어제와 무엇이 다른가 (5분)

    어제 chat3.py 오늘 에이전트
    문서를 넣는 곳 프롬프트 안 업로드 → 지식(Knowledge)
    문서 크기 토큰 한도까지만 수백 페이지도 가능
    찾는 방식 전부 다 보냄 필요한 부분만 찾아서 씀
    할 수 있는 일 답하기 답하기 + 도구로 행동하기

    ★ 에이전트 4요소 — 3강에서 배운 그대로입니다

    요소 오늘 어디서
    모델 1절에서 선택
    지침 (Instructions) 1절에서 작성
    지식 (Knowledge) 2절에서 파일 업로드
    도구 (Tools) 3절에서 확인

    화면에서는 지식과 도구가 한 덩어리로 보입니다. 파일 업로드 버튼이 도구 아래 있습니다. 개념은 네 가지로 나뉘지만 UI 구분은 다르다는 것만 알아두세요 (2절에서 다시 짚습니다).

    1. 에이전트 만들기 (12분)

    1. ai.azure.com → 내 프로젝트 홈 → 「에이전트 빌드」 카드 → 에이전트 만들기

      왼쪽 메뉴를 찾지 마세요

      우상단 새 Foundry 토글이 켜진 화면 기준입니다. 메뉴는 위쪽(홈 · 검색 · 빌드 · 작업 · 관리 · 문서)에 있고, 에이전트는 홈 화면 왼쪽 첫 카드에서 바로 만듭니다.

    2. 아래처럼 설정합니다.

      항목 값
      모델 gpt-5.4-mini (Lab 02에서 배포한 것)
      이름 hr-agent ← 코드에서 쓰니 정확히 이대로

    3. 지침(Instructions) 에 아래를 붙여넣습니다.

      너는 사내 인사 규정 도우미다.
- 제공된 규정 문서와 인사 시스템 데이터만 근거로 답한다.
- 휴가 신청은 잔여 연차를 먼저 확인한 뒤 진행한다.
- 규정에 없는 내용은 '확인 필요'라고 답하고 임의로 처리하지 않는다.

    4. 이름을 hr-agent 로 바꿉니다.

      새 빌더는 만들 때 이름을 묻지 않고 silver-agent-hxmlzpz35c 같은 임의의 이름을 자동으로 붙입니다. 화면 위쪽의 에이전트 이름을 클릭하거나 세부 정보 탭에서 바꿀 수 있습니다.

    5. 저장합니다.

    이름을 꼭 hr-agent 로 하세요 — 안 바꾸면 Lab 09가 통째로 막힙니다

    Lab 09의 코드가 agents.get("hr-agent") 로 이름을 찍어서 에이전트를 찾습니다. 자동 생성된 이름 그대로 두면 에이전트를 찾을 수 없다는 오류가 납니다. 대소문자와 공백까지 정확히 hr-agent 여야 합니다.

    지침은 시스템 메시지와 같은 건가요

    역할이 같습니다. 어제 SYSTEM 변수에 넣던 걸 포털에 저장해 두는 것입니다. 코드에서 매번 보낼 필요가 없어집니다.

    2. 지식 붙이기 — 파일 업로드 (15분)

    먼저 규정 문서를 만듭니다

    메모장이나 VS Code로 휴가규정.txt 를 만들고 아래를 넣어 저장하세요.

    [사내 휴가 규정]

제3조 (연차)
입사 1년 이상 직원은 연 15일의 연차를 부여한다.
입사 1년 미만 직원은 1개월 개근 시 1일의 연차를 부여한다.

제4조 (신청)
연차는 사용 3일 전까지 인사 시스템으로 신청한다.
3일 이내 긴급 신청은 팀장 승인을 받아야 한다.

제5조 (반차)
반차는 오전 09:00~13:00, 오후 13:00~18:00 중 선택한다.
반차 2회는 연차 1일로 계산한다.

제7조 (이월)
미사용 연차는 다음 해로 이월되지 않는다.
단, 회사 사정으로 사용하지 못한 경우 최대 5일까지 이월할 수 있다.

    에이전트에 붙입니다

    1. 에이전트 화면 → 도구(Tools) 섹션
    2. 파일 업로드 버튼을 누릅니다 (추가 ▾ 옆에 있습니다)
    3. 휴가규정.txt 를 업로드합니다
    4. 인덱싱이 끝날 때까지 기다립니다 (1~3분)

    지식 섹션이 아니라 도구 섹션입니다

    지식 섹션의 추가 를 누르면 Foundry IQ에 연결 하나만 나옵니다. 그게 맞습니다.

    Foundry IQ 는 여러 에이전트가 함께 쓰는 중앙 지식 베이스입니다. 우리처럼 이 에이전트 하나에만 파일을 붙이는 건 도구의 파일 업로드 입니다. 같은 파일 검색(File search) 기능인데 붙이는 범위가 다릅니다.

    지금 1~3분 동안 무슨 일이 일어나나 — 임베딩

    업로드한 파일을 그냥 저장하는 게 아닙니다. Foundry 가 이 사이에 하는 일은

    1. 문서를 조각(chunk) 으로 자르고
    2. 각 조각을 임베딩 모델에 넣어 숫자 벡터로 바꾸고
    3. 그 벡터를 검색할 수 있게 저장합니다

    3강에서 배운 임베딩이 여기서 쓰입니다. 의미가 비슷한 문장은 비슷한 방향의 벡터가 되고, 그래서 글자가 달라도 의미로 찾을 수 있게 됩니다. 기다리는 시간이 곧 벡터를 만드는 시간입니다.

    지식 도구 세 가지 — 3강에서 배운 것

    도구 무엇 화면에서
    파일 검색 업로드한 문서에서 찾습니다 ← 오늘 씁니다 도구 → 파일 업로드
    웹 검색 최신 정보를 가져옵니다 도구 → 웹 검색
    데이터 원본 연결 DB·API를 조회합니다 도구 → 추가 ▾

    셋 다 도구 아래 있습니다. 에이전트 4요소에서 "지식"에 해당하지만, Foundry 화면은 붙이는 방식(이 에이전트에만 / 여러 에이전트가 공유)으로 나눠 놨습니다.

    3. 플레이그라운드에서 테스트 (8분)

    에이전트 화면의 플레이그라운드 또는 테스트 창에서 물어봅니다.

    질문 기대하는 답
    연차가 며칠인가요? 15일 + 제3조 근거
    반차 2번 쓰면 연차 며칠 쓴 건가요? 1일 + 제5조
    미사용 연차는 이월되나요? 원칙적으로 안 됨, 예외 5일 + 제7조
    병가는 며칠인가요? 확인 필요 (규정에 없음)
    쉬는 날 며칠 받나요? 15일 + 제3조 ← 규정에 "쉬는 날"은 한 글자도 없습니다

    세 번째 질문이 핵심입니다

    제7조는 원칙과 예외가 같이 있습니다. 에이전트가 둘 다 찾아서 답하면 "문서에서 필요한 부분을 찾아 쓰고 있다"는 뜻입니다.

    다섯 번째 질문이 임베딩의 증거입니다

    규정 어디에도 "쉬는 날" 이라는 말은 없습니다. 글자로 찾는 검색이었다면 아무것도 못 찾습니다. 그런데 답이 나옵니다.

    질문도 벡터로 바뀌어서, "쉬는 날" 벡터와 "연차" 벡터가 가까웠기 때문입니다. 이게 의미 기반 검색입니다.

    어제와 비교해 보세요

    chat3.py 는 규정 전체를 매번 보냈습니다. 에이전트는 질문에 관련된 부분만 찾아 씁니다. 문서가 300페이지여도 같은 방식으로 동작합니다.

    어떻게 관련된 부분만 고를까요. 세 단계입니다.

    무슨 일 쓰는 모델
    1 올린 문서를 조각내 벡터로 만들어 저장 (업로드 때 끝남) 임베딩 모델
    2 질문을 벡터로 바꿔 가까운 조각만 찾음 임베딩 모델
    3 찾은 조각 + 질문 → 답을 생성 채팅 모델

    이 구조를 RAG(검색 증강 생성)라고 부릅니다. 7강 5-C 에서 본 그림입니다.

    ★ 시험 포인트 — 모델이 두 개 쓰입니다

    "의미 기반 검색을 구현하려면 어떤 모델을 배포해야 하나?" → 임베딩 모델입니다. 채팅 모델은 답을 쓰는 모델이지 찾는 모델이 아닙니다. 선택지에 꼭 섞여 나옵니다.

    넣는 것 나오는 것
    채팅 모델 텍스트 텍스트 — 사람이 읽는 답
    임베딩 모델 텍스트 숫자 벡터 — 의미의 좌표

    오늘 「파일 검색」을 켜는 것만으로 Foundry 가 둘 다 알아서 썼습니다. 직접 배포하지 않았을 뿐, 뒤에서는 임베딩 모델이 돌고 있었습니다.

    4. 도구(Tools) 둘러보기 (5분)

    지금은 지식만 붙였지만, 에이전트는 행동도 할 수 있습니다.

    도구 무엇
    연결된 서비스 호출 외부 시스템의 기능을 부릅니다
    코드 실행 계산·데이터 처리를 수행합니다
    시스템 연동 업무 시스템에 쓰기 작업을 합니다

    ★ 쓰기 작업에는 승인이 필요합니다

    "휴가를 신청해줘" 같은 요청은 실제로 시스템을 바꿉니다. 그래서 에이전트가 도구를 쓰기 전에 사람이 승인하는 단계를 둡니다.

    2강에서 배운 책임(Accountability) 원칙이 여기서 구현됩니다. 시험에 "에이전트가 외부 시스템을 변경하기 전에 필요한 것은?" → 사용자 승인으로 나옵니다.

    지금은 도구 목록만 눈으로 확인하고 넘어갑니다. 추가하지 마세요.

    5. ✅ 체크포인트

    여기까지 됐으면 통과입니다

    • [ ] 에이전트 hr-agent 가 만들어져 있다
    • [ ] 지침에 "확인 필요" 규칙이 들어 있다
    • [ ] 지식에 휴가규정.txt 가 인덱싱 완료 상태다
    • [ ] 네 가지 질문에 근거 조항과 함께 답한다
    • [ ] "병가"에 확인 필요라고 답한다

    에이전트 이름이 hr-agent 인지 다시 확인하세요. 다음 랩에서 씁니다.

    🔧 안 될 때

    에이전트를 생성할 권한이 없습니다 — 노란 배너가 뜹니다

    화면 위쪽에 노란 띠로 "관리자에게 Foundry 사용자 역할을 할당해 달라고 요청합니다" 가 나오는 경우입니다.

    먼저 로그아웃했다가 다시 로그인해 보세요. 대부분 이걸로 풀립니다. 역할은 이미 부여돼 있는데, 로그인한 채로 있으면 옛 권한 정보가 그대로 남아 있어서 생기는 일입니다.

    재로그인해도 그대로면 손을 드세요. 역할 부여가 누락된 것입니다.

    리소스는 만들 수 있는데 왜 에이전트는 안 되나요

    Azure 권한은 두 종류입니다.

    하는 일 역할
    제어 평면 리소스를 만들고 지운다 Owner
    데이터 평면 그 안의 내용을 다룬다 Foundry User

    에이전트 생성은 데이터 평면입니다. 그런데 Owner 에는 데이터 평면 권한이 들어 있지 않습니다. 그래서 리소스 그룹의 소유자여도, 심지어 구독 소유자여도 이 배너를 봅니다. 버그가 아니라 설계입니다.

    강사용 — 역할 부여 명령

    az role assignment create \
  --assignee "ai901-NN@도메인" \
  --role "Foundry User" \
  --scope "/subscriptions/<구독ID>/resourceGroups/rg-ai901-NN"

    반영에 1~5분 걸립니다. 부여 후 학생에게 반드시 재로그인시키세요. instructor-setup/provision-students.sh 는 Owner 와 Foundry User 를 함께 부여합니다.

    에이전트 메뉴가 안 보입니다
    1. 우상단 새 Foundry 토글이 켜져 있는지 보세요. 꺼져 있으면 옛 화면이라 왼쪽 사이드바로 나옵니다.
    2. 프로젝트 안에 있어야 보입니다. 리소스 화면이 아니라 프로젝트 홈인지 확인하세요.
    3. 그래도 안 보이면 상단 검색창(⌘K)에 agent 를 입력해 보세요.
    지식 섹션에 Foundry IQ 연결만 있고 파일 업로드가 없습니다

    정상입니다. 파일 업로드는 도구 섹션에 있습니다.

    지식 → 추가 가 아니라, 도구 섹션의 파일 업로드 버튼을 누르세요. 2절을 다시 보시면 됩니다.

    에이전트 이름이 silver-agent-... 같은 이상한 이름입니다

    새 빌더가 자동으로 붙인 이름입니다. 그대로 두면 Lab 09에서 막힙니다.

    화면 위쪽의 에이전트 이름을 클릭하거나 세부 정보 탭에서 hr-agent 로 바꾸세요.

    파일 업로드 후 인덱싱이 끝나지 않습니다
    • 3분 넘게 걸리면 새로고침해 보세요
    • 파일이 너무 크거나 형식이 안 맞을 수 있습니다. .txt 로, 1KB 정도면 충분합니다
    • 한글 파일명이 문제가 되면 rules.txt 로 바꿔 보세요
    근거 조항을 인용하지 않습니다
    1. 지식이 인덱싱 완료 상태인지 확인
    2. 지침에 한 줄 추가: "답변에 반드시 근거 조항을 '(제N조)' 형식으로 표시한다."
    3. 저장 후 새 대화로 다시 시도 (기존 대화는 옛 지침을 쓸 수 있습니다)
    규정에 없는 것도 지어냅니다

    지침을 강하게 바꿉니다.

    규정 문서에 없는 내용은 반드시 '확인 필요'라고만 답한다. 추측하지 않는다.
    모델을 선택할 수 없습니다

    Lab 02에서 배포한 모델이 배포 완료 상태인지 확인하세요. 배포가 없으면 에이전트를 만들 수 없습니다.
