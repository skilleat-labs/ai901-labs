    Lab 10 — 텍스트 분석 두 가지 방법

    이 실습에서 하는 것

    고객 리뷰에서 감정 · 엔터티 · 키 구문 · 요약을 뽑습니다. 그리고 범용 모델과 전용 서비스 중 무엇을 쓸지 판단하는 기준을 잡습니다.

    선행 Lab 04 완료 · 예상 시간 45분 · 비용 약 $0.03 미만

    0. 두 가지 길이 있습니다 (5분)

    ★★ 10강의 핵심이자 시험 최다 출제 지점

    범용 모델 (gpt-5.4-mini) 전용 서비스 (Azure Language)
    방식 프롬프트로 시킨다 메서드를 호출한다
    반환 자유 텍스트 (형식 요청 가능) 구조화된 결과 + 신뢰도 점수
    장점 유연함 · 여러 작업을 한 번에 일관된 형식 · 점수 · 저렴
    단점 형식이 흔들릴 수 있음 정해진 작업만

    판단 기준 — "시스템이 쓸 거면 전용 서비스"로 외우면 틀립니다. 범용 모델도 JSON 을 뱉게 할 수 있습니다 (이 랩에서 바로 그걸 합니다).

    진짜 갈림길은 네 가지입니다.

    이런 조건이면 고를 것
    신뢰도 점수(confidence score) 가 필요하다 전용 서비스
    스키마가 절대 흔들리면 안 된다 (계약된 형식) 전용 서비스
    대량 처리라 단가·지연이 중요하다 전용 서비스
    작업이 정해진 목록에 없다 (요약 + 번역 + 분류를 한 번에 등) 범용 모델

    한 줄로 줄이면 — 정해진 작업을 확실하게는 전용 서비스, 정해지지 않은 작업을 유연하게는 범용 모델입니다.

    오늘은 범용 모델로 직접 만들고, 전용 서비스는 차이를 눈으로 비교합니다.

    1. analyze_general.py (15분)

    import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    base_url=os.getenv("AZURE_OPENAI_ENDPOINT"),
    api_key=os.getenv("API_KEY"))

review = """지난주에 강남점에서 산 무선 이어폰인데요,
음질은 생각보다 훨씬 좋았습니다. 다만 배송이 5일이나 걸려서 답답했고
포장도 좀 허술했어요. 김민수 매니저님이 친절하게 응대해 주신 건 좋았습니다."""

prompt = f"""다음 고객 리뷰를 분석해서 JSON으로만 답해라.

{{
  "감정": "긍정 | 부정 | 중립",
  "엔터티": ["사람·장소·조직·제품"],
  "키구문": ["핵심 주제어 3개"],
  "요약": "한 문장"
}}

리뷰:
{review}"""

message = client.responses.create(
    model=os.getenv("MODEL_DEPLOYMENT_NAME"),
    input=prompt)

print(message.output_text)

    python analyze_general.py

    나오는 결과 — 예시

    {
  "감정": "부정",
  "엔터티": ["강남점", "무선 이어폰", "김민수 매니저"],
  "키구문": ["음질", "배송 지연", "포장 허술"],
  "요약": "음질과 응대는 좋았지만 배송이 늦고 포장이 허술해 전반적으로 부정적인 리뷰다."
}

    ★ 감정이 부정으로 나와도, 중립으로 나와도 맞습니다

    옆 사람과 값이 다를 겁니다. 틀린 게 아니라 이 랩의 핵심입니다.

    이 리뷰에는 좋은 점(음질·응대)과 나쁜 점(배송·포장)이 둘 다 있습니다. 그런데 우리가 준 선택지는 긍정 | 부정 | 중립 셋뿐입니다. "혼합"이라는 칸이 없으니 모델이 셋 중 하나를 고를 수밖에 없습니다. 나쁜 점을 더 무겁게 보면 "부정", 둘이 상쇄된다고 보면 "중립" 입니다.

    같은 리뷰를 전용 서비스에 넣으면 mixed 라고 답합니다. 3절에서 확인합니다. 엔터티나 키구문도 개수·표기가 조금씩 다를 수 있습니다 (김민수 vs 김민수 매니저).

    네 가지 작업을 한 번에 했습니다

    전용 서비스였다면 감정 분석 · 엔터티 인식 · 키 구문 추출 · 요약을 각각 따로 호출해야 합니다. 범용 모델의 장점이 이겁니다.

    2. 약점을 직접 확인하세요 (5분)

    같은 코드를 3번 더 돌리고, 세 결과를 나란히 놓고 보세요. 무엇이 같고 무엇이 달라지는지가 핵심입니다.

    보는 곳 대개 이렇게 됩니다 그래서 뭐가 문제인가
    감정 · 엔터티 대체로 같게 나옵니다 판정 자체는 꽤 안정적입니다
    키구문 "포장 허술" → "포장 상태" 처럼 표기가 바뀝니다 같은 뜻인데 문자열이 달라 집계가 안 됩니다
    요약 매번 다른 문장이 나옵니다 생성이라 표현이 고정되지 않습니다
    신뢰도 점수 아예 없습니다 이 판정을 얼마나 믿을지 알 수 없습니다

    세 번 다 비슷하게 나왔는데요?

    그게 정상입니다. 크게 흔들리는 걸 보라는 게 아닙니다. 같은 입력인데 요약 문장과 키구문 표기가 매번 조금씩 달라진다는 것, 그거면 충분합니다.

    리뷰 1,000건을 이 코드로 돌려 "포장" 관련 불만을 세야 한다고 해보세요. 포장 허술 · 포장 상태 · 포장 이 섞여 나오면 숫자를 못 셉니다. 전용 서비스는 같은 입력에 같은 라벨과 같은 점수를 줍니다. 그 차이가 선택의 기준입니다.

    여기가 범용 모델의 한계입니다

    • 표현이 고정되지 않습니다 → 결과를 모아서 집계·비교하기 어렵습니다
    • 가끔 JSON 앞뒤에 설명이 붙습니다 → 파싱이 깨집니다
    • 신뢰도 점수가 없습니다 → "이 감정 판정을 얼마나 믿을 수 있나"를 알 수 없습니다

    온도를 0으로 낮추면 많이 안정됩니다 — 다만 보장은 아닙니다. (Lab 06)

    message = client.responses.create(
    model=os.getenv("MODEL_DEPLOYMENT_NAME"),
    input=prompt,
    temperature=0)

    3. 전용 서비스는 무엇이 다른가 — 직접 돌려봅니다 (10분)

    새 리소스도, 새 키도, 신청 절차도 없습니다

    Lab 01에서 만든 Foundry 리소스는 Azure AI Services(멀티 서비스) 리소스입니다. 포털 어딘가에 "Language 신청" 버튼이 있는 게 아니라, 리소스를 만든 순간 이미 들어 있습니다.

    리소스 하나에 들어 있는 것 쓰는 곳
    모델 (gpt) Lab 02~09
    Language — 감정 · 엔터티 · 키구문 · PII 지금
    Speech — STT · TTS Lab 11
    Vision · 문서 이해 Lab 13~15

    키는 지금 쓰는 API_KEY 그대로고, 주소만 다릅니다.

    주소
    모델 호출 (Lab 04~) https://<리소스명>.openai.azure.com/openai/v1
    Language 호출 (지금) https://<리소스명>.cognitiveservices.azure.com/

    패키지를 설치합니다.

    requirements.txt 에 추가
    azure-ai-textanalytics==5.4.0

    pip install -r requirements.txt

    .env 에 한 줄 추가합니다. <리소스명> 은 지금 쓰는 엔드포인트 주소에서 그대로 가져오세요.

    LANGUAGE_ENDPOINT=https://<리소스명>.cognitiveservices.azure.com/
    analyze_language.py
    import os
from dotenv import load_dotenv
from azure.core.credentials import AzureKeyCredential
from azure.ai.textanalytics import TextAnalyticsClient

load_dotenv()
client = TextAnalyticsClient(
    endpoint=os.getenv("LANGUAGE_ENDPOINT"),
    credential=AzureKeyCredential(os.getenv("API_KEY")))

review = """지난주에 강남점에서 산 무선 이어폰인데요,
음질은 생각보다 훨씬 좋았습니다. 다만 배송이 5일이나 걸려서 답답했고
포장도 좀 허술했어요. 김민수 매니저님이 친절하게 응대해 주신 건 좋았습니다."""

result = client.analyze_sentiment(documents=[review])[0]

print("문서 전체:", result.sentiment)
print("  긍정", result.confidence_scores.positive,
      "/ 중립", result.confidence_scores.neutral,
      "/ 부정", result.confidence_scores.negative)

for s in result.sentences:
    print(f"  [{s.sentiment}] {s.text.strip()}")

    python analyze_language.py

  [negative] 다만 배송이 5일이나 걸려서 답답했고 포장도 좀 허술했어요.
  [positive] 김민수 매니저님이 친절하게 응대해 주신 건 좋았습니다.

    ★ 2절에서 본 것과 비교하세요

    범용 모델은 긍정 | 부정 | 중립 중 하나를 골라야 했습니다. 그래서 "부정" 이 나왔죠. 전용 서비스는 mixed 라고 답합니다. 혼합을 혼합이라고 말할 수 있습니다.

    거기에 점수가 붙고, 문장별로 어디가 긍정이고 어디가 부정인지까지 나눠 줍니다. 그리고 몇 번을 돌려도 같은 값입니다. 2절에서 요약 문장이 매번 달라지던 것과 반대입니다.

    ★ 반환값의 차이가 시험에 나옵니다

    범용 모델 전용 서비스
    감정 "부정" · "중립" — 셋 중 하나를 고른 문자열 mixed — 혼합을 혼합이라고 답한다
    신뢰도 없다 confidence_scores (0.65 / 0.03 / 0.32)
    세분화 문서 하나에 값 하나 문장별 감정까지
    형식 요청한 대로 (표현이 흔들림) 항상 같은 객체 · 같은 값
    할 수 있는 것 요약·번역·분류를 한 번에 감정 하나만, 대신 확실하게

    "신뢰도 점수가 필요하다" 가 문제에 나오면 → 전용 서비스입니다. 이게 3강에서 배운 "생성형 AI가 이전 AI를 대체하지 않는다"의 실체입니다.

    비용 — 종량제입니다

    우리 리소스는 S0(종량제) 라 무료 한도가 붙지 않습니다. 요금은 텍스트 레코드 1,000건당 약 $1 이고, 1건 = 1,000자 이하 한 덩어리입니다.

    오늘 리뷰는 100자 남짓이라 한 번 호출 = 1건입니다. 1인이 몇 번 돌려도 1센트가 안 되고, 교실 전체로도 10센트 수준입니다.

    4. 전용 리소스를 직접 만들어 호출합니다 (10분)

    3절은 이미 있는 리소스로 호출했습니다. 이번에는 내가 하나 더 만들어서 같은 코드를 돌립니다. 실무에서는 Language 만 쓰는 팀이 전용 리소스를 따로 두는 경우가 많습니다.

    ★ 만들 때 고르는 종류가 중요합니다 — Language service 가 아니라 Azure AI Services

    포털에 Language service 라는 항목이 따로 있습니다. 그런데 교육용 구독에서는 이게 막힙니다.

    만들려는 것 교육용 구독에서
    Language service · 무료 F0 구독당 딱 1개 — 전원이 못 만듭니다
    Language service · 표준 S0 차단됨 (구독 기능 제한)
    Azure AI Services · S0 됩니다 ← 이걸로 만듭니다

    그리고 Azure AI Services(= 포털의 Microsoft Foundry) 로 만들면 Language 뿐 아니라 Speech · Vision 도 함께 들어옵니다. Lab 01에서 만든 것과 같은 종류입니다.

    그래서 이 과정에서 따로 만들 서비스가 사실상 없습니다. Foundry 리소스 하나가 전부입니다.

    ① 포털에서 만들기 (3분)

    1. portal.azure.com → 리소스 만들기

    2. 검색창에 Azure AI Services 를 칩니다. 결과에 「Microsoft Foundry」 가 나오는데 그게 맞습니다. 그걸 선택 → 만들기

      이름이 통합됐습니다 — Azure AI Services = Microsoft Foundry

      예전 이름이 Azure AI Services(멀티 서비스), 지금 포털 이름이 Microsoft Foundry 입니다. 검색어로 Azure AI Services 를 쳐도 Foundry 가 나오는 이유입니다. Lab 01에서 만든 것과 같은 종류입니다 (리소스 종류로는 AIServices).

    3. 값을 채웁니다.

      칸 넣을 값
      구독 그대로
      리소스 그룹 내 그룹 rg-ai901-<번호>
      지역 East US 2
      이름 lang-ai901-<번호>
      가격 책정 계층 Standard S0

    4. 프로젝트 이름 칸이 같이 나오면 기본값 그대로 둡니다 (Lab 01과 같은 화면입니다)

    5. 책임 있는 AI 고지 동의 체크가 있으면 체크합니다
    6. 검토 + 만들기 → 만들기. 1~2분 걸립니다

    ② 키와 엔드포인트 복사 (2분)

    1. 만들어진 리소스로 이동 → 왼쪽 키 및 엔드포인트
    2. 키 1 과 엔드포인트를 복사합니다

    .env 에 두 줄을 추가합니다. 기존 값은 지우지 마세요.

    LANGUAGE_ENDPOINT2=https://lang-ai901-<번호>.cognitiveservices.azure.com/
LANGUAGE_KEY2=복사한_키1

    ③ 같은 코드를 그대로 돌립니다 (3분)

    analyze_language.py 에서 두 줄만 바꿉니다.

    client = TextAnalyticsClient(
    endpoint=os.getenv("LANGUAGE_ENDPOINT2"),      # ← 2 를 붙였습니다

    python analyze_language.py

    결과가 3절과 똑같이 나옵니다

    mixed · 긍정 0.65 / 중립 0.03 / 부정 0.32 · 문장별 감정. 코드는 한 줄도 안 바뀌었습니다.

    바뀐 건 어느 리소스로 가느냐뿐입니다. Lab 01에서 "리소스는 결제 · 지역 · 할당량의 단위"라고 했죠. 그게 이겁니다. 키와 엔드포인트가 곧 "어느 리소스로 보낼지"를 정합니다.

    ④ 확인했으면 바로 지웁니다 (2분)

    확인이 끝난 리소스는 그 자리에서 지웁니다. 4일차까지 미루지 마세요. AI Services 는 쓰지 않으면 과금이 없지만, 만들었으면 지운다를 몸에 붙이는 게 이 절의 또 다른 목적입니다.

    1. portal.azure.com → 검색창에 리소스 그룹 → 내 그룹
    2. 방금 만든 lang-ai901-<번호> 왼쪽 체크박스를 켭니다
    3. 상단 삭제 → 확인란에 delete 입력 → 삭제
    az cognitiveservices account delete \
  -n lang-ai901-<번호> -g rg-ai901-<번호>

    ★ 특히 이것만은 만들자마자 지우세요 — 「검색 서비스」(Azure AI Search)

    포털에서 리소스를 찾다 보면 「검색 서비스」 / Azure AI Search 가 눈에 띕니다. 이 과정에서는 쓰지 않습니다. 그런데 실수로 만들면 가장 비쌉니다.

    과금 방식
    Language · Speech · 모델 호출한 만큼 — 안 쓰면 0원
    Azure AI Search (표준) 켜져 있는 시간만큼 — 안 써도 시간당 과금

    표준 계층은 시간당 약 $0.33 입니다. 하루 켜두면 $8, 한 달이면 $240 쯤 됩니다. 만들었다면 지금 바로 지우세요.

    az resource list --resource-type Microsoft.Search/searchServices -o table
az search service delete -n <이름> -g rg-ai901-<번호> --yes

    그럼 Azure AI Search 는 언제 쓰나요

    문서를 쪼개서 색인해 두고 질문과 가까운 조각을 찾아오는 검색 엔진입니다. RAG 의 검색 부분이죠. 문서가 수천 쪽이라 프롬프트에 다 못 넣을 때 씁니다.

    우리는 Lab 08에서 에이전트에 파일을 올려 같은 일을 했습니다. 그건 Foundry 에 내장된 기능이라 검색 서비스를 따로 만들 필요가 없습니다. AI-901 시험 범위에도 Azure AI Search 리소스를 직접 만드는 내용은 없습니다.

    🔧 안 될 때

    JSON 앞뒤에 설명이 붙습니다

    프롬프트에 강하게 지시하세요.

    JSON만 출력하고 다른 말은 하지 마라. 코드블록 표시(```)도 쓰지 마라.

    그리고 temperature=0 을 넣으세요. 실무에서는 파싱 실패에 대비해 try/except 로 감싸고 재시도합니다.

    한글이 깨집니다

    파일을 UTF-8 로 저장했는지 확인하세요. VS Code 우하단에서 인코딩을 확인할 수 있습니다.

    f-string 안의 중괄호에서 오류가 납니다

    f-string 안에서 JSON의 { 는 {{ 로 써야 합니다. 위 코드가 그렇게 되어 있으니 그대로 복사하세요.

    Language 호출에서 401 · 404 가 납니다

    주소부터 확인하세요. .openai.azure.com 이 아니라 .cognitiveservices.azure.com 입니다. 끝의 슬래시까지 포함하고, /openai/v1 같은 경로는 붙이지 않습니다.

    print(os.getenv("LANGUAGE_ENDPOINT"))

    주소가 맞는데도 안 되면 리소스 종류를 보세요. Language 는 AIServices 리소스에만 들어 있습니다.

    az cognitiveservices account list -o table

    Kind 가 AIServices 면 정상입니다. OpenAI 로 되어 있으면 Azure OpenAI 전용으로 만들어진 것이라 Language 가 없습니다. 손을 드세요 — 강사가 확인해 드립니다.

    (강사용) 그 경우 Azure 포털에서 리소스 만들기 → "Language service" 로 따로 하나 만들면 됩니다. 가격 계층에서 F0(무료) 를 고를 수 있고, 만든 뒤 키와 엔드포인트를 그 학생에게 주면 이어서 진행됩니다.
