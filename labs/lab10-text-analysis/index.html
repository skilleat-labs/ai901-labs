    Lab 10 — 텍스트 분석 두 가지 방법

    이 실습에서 하는 것

    고객 리뷰에서 감정 · 엔터티 · 키 구문 · 요약을 뽑습니다. 그리고 범용 모델과 전용 서비스 중 무엇을 쓸지 판단하는 기준을 잡습니다.

    선행 Lab 04 완료 · 예상 시간 30분 · 비용 약 $0.03 미만

    0. 두 가지 길이 있습니다 (5분)

    ★★ 10강의 핵심이자 시험 최다 출제 지점

    범용 모델 (gpt-5.4-mini) 전용 서비스 (Azure Language)
    방식 프롬프트로 시킨다 메서드를 호출한다
    반환 자유 텍스트 (형식 요청 가능) 구조화된 결과 + 신뢰도 점수
    장점 유연함 · 여러 작업을 한 번에 일관된 형식 · 점수 · 저렴
    단점 형식이 흔들릴 수 있음 정해진 작업만

    판단 기준 — "시스템이 쓸 거면 전용 서비스"로 외우면 틀립니다. 범용 모델도 JSON 을 뱉게 할 수 있습니다 (이 랩에서 바로 그걸 합니다).

    진짜 갈림길은 네 가지입니다.

    이런 조건이면 고를 것
    신뢰도 점수(confidence score) 가 필요하다 전용 서비스
    스키마가 절대 흔들리면 안 된다 (계약된 형식) 전용 서비스
    대량 처리라 단가·지연이 중요하다 전용 서비스
    작업이 정해진 목록에 없다 (요약 + 번역 + 분류를 한 번에 등) 범용 모델

    한 줄로 줄이면 — 정해진 작업을 확실하게는 전용 서비스, 정해지지 않은 작업을 유연하게는 범용 모델입니다.

    오늘은 범용 모델로 직접 만들고, 전용 서비스는 차이를 눈으로 비교합니다.

    1. analyze_general.py (15분)

    import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    base_url=os.getenv("AZURE_OPENAI_ENDPOINT"),
    api_key=os.getenv("API_KEY"))

review = """지난주에 강남점에서 산 무선 이어폰인데요,
음질은 생각보다 훨씬 좋았습니다. 다만 배송이 5일이나 걸려서 답답했고
포장도 좀 허술했어요. 김민수 매니저님이 친절하게 응대해 주신 건 좋았습니다."""

prompt = f"""다음 고객 리뷰를 분석해서 JSON으로만 답해라.

{{
  "감정": "긍정 | 부정 | 중립",
  "엔터티": ["사람·장소·조직·제품"],
  "키구문": ["핵심 주제어 3개"],
  "요약": "한 문장"
}}

리뷰:
{review}"""

message = client.responses.create(
    model=os.getenv("MODEL_DEPLOYMENT_NAME"),
    input=prompt)

print(message.output_text)

    python analyze_general.py

    기대 결과

    {
  "감정": "중립",
  "엔터티": ["강남점", "김민수", "무선 이어폰"],
  "키구문": ["음질", "배송 지연", "포장"],
  "요약": "음질은 만족스러웠으나 배송과 포장에 불만이 있었다."
}

    네 가지 작업을 한 번에 했습니다

    전용 서비스였다면 감정 분석 · 엔터티 인식 · 키 구문 추출 · 요약을 각각 따로 호출해야 합니다. 범용 모델의 장점이 이겁니다.

    2. 약점을 직접 확인하세요 (5분)

    같은 코드를 3번 더 돌려 보세요.

    확인할 것 결과
    JSON 형식이 매번 똑같은가?
    엔터티 개수가 일정한가?
    신뢰도 점수가 있는가?

    여기가 범용 모델의 한계입니다

    • 가끔 JSON 앞뒤에 설명이 붙습니다 → 파싱이 깨집니다
    • 신뢰도 점수가 없습니다 → "이 감정 판정을 얼마나 믿을 수 있나"를 알 수 없습니다

    온도를 0으로 낮추면 많이 안정됩니다. (Lab 06)

    message = client.responses.create(
    model=os.getenv("MODEL_DEPLOYMENT_NAME"),
    input=prompt,
    temperature=0)

    3. 전용 서비스는 무엇이 다른가 (5분)

    Azure Language SDK를 쓰면 이런 형태로 돌아옵니다.

    # analyze_language.py — 참고용 (오늘은 실행하지 않습니다)
result = client.analyze_sentiment(documents=[review])[0]

print(result.sentiment)                    # "mixed"
print(result.confidence_scores.positive)   # 0.62
print(result.confidence_scores.negative)   # 0.31

    ★ 반환값의 차이가 시험에 나옵니다

    범용 모델 전용 서비스
    감정 "중립" (문자열) sentiment + confidence_scores
    형식 요청한 대로 (흔들림) 항상 같은 객체

    "신뢰도 점수가 필요하다" 가 문제에 나오면 → 전용 서비스입니다. 이게 3강에서 배운 "생성형 AI가 이전 AI를 대체하지 않는다"의 실체입니다.

    오늘 실행하지 않는 이유

    Azure Language 리소스를 따로 연결해야 해서 시간이 더 듭니다. 선택의 기준을 아는 게 시험과 실무에 더 중요합니다.

    4. ✅ 체크포인트

    여기까지 됐으면 통과입니다

    • [ ] analyze_general.py 가 JSON으로 네 가지를 뽑았다
    • [ ] 여러 번 돌려 결과가 흔들리는 것을 확인했다
    • [ ] temperature=0 으로 안정되는 것을 확인했다
    • [ ] 언제 전용 서비스를 쓰는지 한 문장으로 말할 수 있다

    🔧 안 될 때

    JSON 앞뒤에 설명이 붙습니다

    프롬프트에 강하게 지시하세요.

    JSON만 출력하고 다른 말은 하지 마라. 코드블록 표시(```)도 쓰지 마라.

    그리고 temperature=0 을 넣으세요. 실무에서는 파싱 실패에 대비해 try/except 로 감싸고 재시도합니다.

    한글이 깨집니다

    파일을 UTF-8 로 저장했는지 확인하세요. VS Code 우하단에서 인코딩을 확인할 수 있습니다.

    f-string 안의 중괄호에서 오류가 납니다

    f-string 안에서 JSON의 { 는 {{ 로 써야 합니다. 위 코드가 그렇게 되어 있으니 그대로 복사하세요.

    엔터티를 제대로 못 찾습니다

    작은 모델의 한계입니다. 리뷰 문장을 더 명확하게 바꾸거나, 프롬프트에 예시를 하나 넣어 보세요 (few-shot).
