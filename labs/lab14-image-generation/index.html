    Lab 14 — 이미지 생성

    이 랩은 강사 데모 + 선택 실습입니다

    이미지 생성 모델은 분당 요청 수(RPM)로 제한됩니다. 신규 구독 기본값은 gpt-image-1-mini 가 분당 12건입니다. 32명이 동시에 돌리면 대부분 대기·실패합니다.

    강사가 먼저 시연하고, 시간이 남으면 조별로 1회씩 돌려 봅니다.

    1. 이미지 모델 배포 (7분 · 강사 시연)

    화면 기준 — 새 Foundry

    이 가이드는 Foundry 포털 우상단 새 Foundry 토글이 켜진 화면 기준입니다. 메뉴는 왼쪽이 아니라 위쪽(홈 · 검색 · 빌드 · 작업 · 관리 · 문서)에 있습니다.

    강사 화면을 보세요

    할당량 때문에 전원이 각자 배포하지 않습니다. 절차만 눈으로 익히세요.

    1. ai.azure.com → 내 프로젝트 홈 → 「모델 살펴보기」 (옛 이름: 모델 카탈로그)
    2. 추론 작업(inference task) 으로 필터링 → 이미지 생성
    3. gpt-image-1-mini 를 선택하고 배포합니다
    4. 배포 이름을 그대로 메모합니다 (기본값은 gpt-image-1-mini)

    이 랩에서만 쓰는 배포입니다

    지금까지 쓴 gpt-5.4-mini 는 이미지를 읽을 수 있지만 만들지는 못합니다. 이미지 생성은 전용 모델을 따로 배포해야 합니다. 4절에서 다시 지웁니다.

    모델이 안 보이면 리전 문제입니다

    이미지 생성 모델은 일부 리전에만 있습니다. Lab 01에서 East US 2 로 만들지 않았다면 여기서 막힙니다 — East US 에는 gpt-image-1-mini 가 없습니다.

    안 보이면 손을 드세요. 강사 화면으로 대체합니다.

    2. 코드로 생성하기 (8분)

    generate_image.py 를 만들고 이 사이트의 코드 블록에서 복사해 넣으세요.

    generate_image.py
    import os, base64
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    base_url=os.getenv("AZURE_OPENAI_ENDPOINT"),
    api_key=os.getenv("API_KEY"))

result = client.images.generate(
    model=os.getenv("IMAGE_DEPLOYMENT_NAME"),
    prompt="눈 내리는 한옥 마을의 저녁 풍경. 따뜻한 창문 불빛.",
    n=1,
    size="1024x1024")

# 이미지 생성 모델은 결과를 base64 문자열로 돌려줍니다
image_bytes = base64.b64decode(result.data[0].b64_json)

with open("generated.png", "wb") as f:
    f.write(image_bytes)

print("저장 완료 — generated.png")

    .env 에 한 줄을 추가합니다. 1절에서 메모한 배포 이름입니다.

    IMAGE_DEPLOYMENT_NAME=gpt-image-1-mini

    python generate_image.py

    폴더에 generated.png 가 생깁니다. 열어서 확인하세요.

    줄별로 하는 일

    줄 하는 일
    client.images.generate(...) 배포한 이미지 모델에 프롬프트를 보냅니다
    result.data[0].b64_json 응답에서 base64 문자열을 꺼냅니다
    base64.b64decode(...) 문자열을 실제 이미지 바이트로 되돌립니다
    open(..., "wb") 바이트를 파일로 씁니다 ("wb" — 텍스트가 아니라 바이너리)

    Lab 13과 방향이 정확히 반대입니다

    Lab 13 Lab 14
    코드 b64encode — 파일을 문자열로 b64decode — 문자열을 파일로
    왜 이미지를 보내려고 이미지를 받았으니

    base64 가 이렇게 양방향으로 쓰입니다. 같은 도구입니다.

    ★ 시험 포인트 — 배포한 모델에 프롬프트를 보낸다

    "프로그래밍 방식으로 이미지를 생성하려면?" → 배포된 이미지 모델에 텍스트 프롬프트를 전송합니다.

    "플레이그라운드에 업로드한다" 같은 선택지는 오답입니다.

    호출 경로는 두 가지가 있습니다.

    경로 언제 코드
    Images API 이미지 생성만 할 때 ← 우리가 쓴 것 client.images.generate(...)
    Responses API 대화 흐름 안에서 도구로 부를 때 tools=[{"type": "image_generation"}]

    둘 다 "배포한 모델에 프롬프트를 보낸다"는 점은 같습니다. 시험에서는 "플레이그라운드에 업로드한다" 류가 오답으로 섞입니다.

    막히면 포털 플레이그라운드로 대체해도 됩니다

    할당량 때문에 실패가 반복되면 플레이그라운드에서 한 장 생성하는 것으로 갈음하세요. 시험이 묻는 건 "어떤 API를 쓰는가"이지 파싱 코드가 아닙니다.

    3. 비디오 생성은 왜 다른가 (3분)

    Sora 같은 비디오 생성은 호출 방식이 다릅니다.

    이미지 생성 비디오 생성
    처리 바로 결과 비동기 — 작업을 제출하고 기다림
    이유 몇 초 리소스를 많이 쓰고 오래 걸림

    ★ 시험에 나옵니다

    "Sora 비디오 생성이 비동기인 이유는?" → 리소스를 많이 사용하고 완료에 시간이 걸리기 때문

    "사용자 상호작용이 필요해서"는 오답입니다.

    비디오는 실습하지 않습니다. 단가가 매우 높습니다.

    여기까지 됐으면 통과입니다

    • [ ] generated.png 가 만들어졌다 (또는 강사 화면으로 확인했다)
    • [ ] b64decode → 파일 저장 흐름을 말할 수 있다
    • [ ] Lab 13의 b64encode 와 방향이 반대인 것을 안다
    • [ ] 비디오 생성이 비동기인 이유를 말할 수 있다

    🔧 안 될 때

    이미지 생성 모델이 카탈로그에 없습니다

    리전 문제입니다. 손을 드세요. 강사 화면으로 대체합니다. 시험 포인트는 전부 전달되니 걱정하지 않으셔도 됩니다.

    b64_json 이 None 이라고 나옵니다

    모델이 base64 가 아니라 URL 로 돌려준 경우입니다.

    print(result.data[0])

    url 필드가 있으면 그 주소를 브라우저에 붙여 확인하세요. gpt-image-1 계열은 항상 base64 로 돌려줍니다.

    IMAGE_DEPLOYMENT_NAME 이 None 이라고 나옵니다

    .env 에 줄을 추가한 뒤 파일을 저장했는지 확인하세요. 그리고 2절의 .env 추가 줄이 MODEL_DEPLOYMENT_NAME 과 다른 이름인지 보세요 (IMAGE_ 로 시작합니다).

    429 — 할당량 초과

    이미지 생성 모델은 구독 전체 할당량이 작습니다. 정상적인 상황입니다.

    1. 30초~1분 뒤 다시 시도
    2. 조별로 한 명씩 순서대로 실행하세요
    3. 계속 실패하면 강사 화면으로 대체합니다
    콘텐츠 정책에 걸렸습니다

    이미지 생성에도 컨텐츠 필터가 적용됩니다 (Lab 03에서 본 그것). 프롬프트를 더 일반적인 내용으로 바꿔 보세요.

    이건 오류가 아니라 가드레일이 정상 동작한 것입니다.
