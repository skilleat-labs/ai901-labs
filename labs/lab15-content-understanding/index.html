    Lab 15 — Content Understanding 으로 영수증 추출

    이 실습에서 하는 것

    영수증 이미지에서 총 금액 · 날짜 · 상호를 각각의 필드 값으로 뽑습니다. 글자를 읽는 게 아니라, 쓸 수 있는 데이터로 만드는 겁니다.

    선행 Lab 13 완료 · 예상 시간 40분 · 비용 약 $0.1 미만

    0. OCR 과 무엇이 다른가 (5분)

    ★★ 5강에서 배운 구분이 여기서 실물이 됩니다

    OCR Content Understanding
    결과 글자 뭉치 이름 붙은 필드 값
    예 "합계 23,000원 2026-03-10" {"총금액": 23000, "날짜": "2026-03-10"}
    다음 단계 직접 파싱해야 함 바로 시스템에 넣을 수 있음

    "필드로 받는다" 가 나오면 Content Understanding 입니다. "글자를 읽는다"면 OCR입니다. 시험에 이 짝으로 나옵니다.

    Lab 13(멀티모달)과도 다릅니다. 멀티모달 모델도 영수증을 읽고 설명할 수 있지만, 매번 같은 형식으로 돌려준다는 보장이 없습니다. CU는 스키마를 미리 정해서 형식을 고정합니다.

    1. 준비 — 될 조건부터 확인 (3분)

    이 랩은 앞선 랩들보다 조건이 까다롭습니다

    아래 네 가지가 모두 맞아야 분석기가 돕니다. 시작 전에 확인하세요.

    조건 확인 방법 안 되면
    1 Foundry 리소스가 있어야 함 Lab 01에서 만든 그것 Lab 01로 돌아가기
    2 리전이 Content Understanding 을 지원해야 함 메뉴가 보이는지로 판단 강사 화면으로 대체
    3 내 계정에 Cognitive Services User 역할 강사가 미리 부여 손 들기
    4 패키지 (코드까지 볼 경우) 아래 참조 —

    ★ 역할이 왜 따로 필요한가 — 시험에도 이어집니다

    Lab 02~07 은 API 키로 호출했습니다. 키 인증은 역할(RBAC)을 거치지 않습니다. 그런데 Content Understanding 과 에이전트는 데이터 평면(data plane) 작업이라 역할이 있어야 합니다.

    역할 담당 이걸로 되는 것
    Contributor 제어 평면 — 리소스·배포를 만들고 지움 Lab 01 · 02
    Cognitive Services User 데이터 평면 — 추론·추출·에이전트 Lab 08 · 09 · 15

    Contributor 만 있으면 리소스는 만들어지는데 분석은 거부됩니다. "만들 수는 있는데 쓸 수가 없다"가 이 구분의 증상입니다.

    패키지 (4절에서 코드를 볼 경우)

    requirements.txt 에 추가
    azure-ai-contentunderstanding==1.1.0

    오늘 실행하지는 않습니다

    4절에서 구조만 봅니다. 설치는 선택입니다 — 집에서 이어서 해보려면 이 버전으로 맞추세요.

    2. 영수증 이미지 (3분)

    영수증 사진을 하나 준비합니다.

    • 지갑에 있는 실물 영수증을 찍어도 되고
    • 없으면 메모장에 영수증처럼 적어서 스크린샷을 찍어도 됩니다
    스킬잇 카페
2026-03-10 14:32
아메리카노  2  9,000
카페라떼    1  5,500
---------------------
합계          14,500

    파일명은 receipt.png 로 저장하세요.

    3. 분석기(Analyzer) 만들기 (15분)

    여기가 핵심입니다. 무엇을 뽑을지 미리 정의합니다.

    1. ai.azure.com → 내 프로젝트 → 도구·지식 → Content Understanding
    2. 새 분석기(Analyzer) 를 만듭니다
    3. 입력 유형을 문서/이미지 로 선택합니다

    필드 스키마 정의

    뽑을 필드를 하나씩 추가합니다.

    필드 이름 유형 설명
    상호 문자열 가게 이름
    날짜 날짜 결제 일자
    총금액 숫자 합계 금액

    설명을 구체적으로 쓰세요

    총금액 에 "합계, 총액, Total 로 표시된 최종 결제 금액" 처럼 적으면 정확도가 올라갑니다. 이게 프롬프트 역할을 합니다.

    테스트

    1. receipt.png 를 업로드하고 분석을 실행합니다
    2. 결과가 필드별로 나오는지 확인합니다
    {
  "상호":   "스킬잇 카페",
  "날짜":   "2026-03-10",
  "총금액": 14500
}

    이게 핵심입니다

    OCR이었다면 "스킬잇 카페 2026-03-10 14:32 아메리카노 2 9,000..." 한 덩어리였을 겁니다. 이름이 붙은 값으로 나왔다는 게 차이입니다.

    4. 분석기 두 종류 (5분)

    미리 만들어진(prebuilt) 분석기 사용자 지정 분석기
    준비 바로 씀 스키마를 직접 정의 ← 방금 한 것
    대상 영수증·명함 등 일반 문서 우리 회사 양식
    장점 빠름 원하는 필드만 정확히

    ★ 시험 포인트

    "사내 전용 양식에서 특정 필드를 뽑아야 한다" → 사용자 지정 분석기 "일반적인 영수증을 처리한다" → 미리 만들어진 분석기로 충분

    5. 코드에서 부르는 구조 (10분)

    오늘은 코드를 실행하지 않습니다

    SDK 패키지와 메서드 이름이 버전에 따라 달라서, 구조만 봅니다. 시험이 묻는 것도 "흐름"이지 정확한 메서드명이 아닙니다.

    # extract.py — 구조
from azure.ai.contentunderstanding import ContentUnderstandingClient
from azure.identity import DefaultAzureCredential

# 1. 클라이언트 생성
client = ContentUnderstandingClient(endpoint, DefaultAzureCredential())

# 2. 분석 작업 제출 — 로컬 파일은 _binary 쪽
with open("receipt.png", "rb") as f:
    poller = client.begin_analyze_binary(
        analyzer_id="receipt-analyzer",
        binary_input=f.read())

# 3. 완료까지 대기 (폴링)
result = poller.result()

# 4. 구조화된 결과 사용 (필드 접근 방식은 SDK 버전에 따라 다릅니다)

    입력이 URL이면 메서드가 다릅니다

    입력 메서드
    로컬 파일 begin_analyze_binary(analyzer_id=..., binary_input=...)
    공개 URL begin_analyze(analyzer_id=..., inputs=[AnalysisInput(url=...)])

    패키지는 azure-ai-contentunderstanding==1.1.0 이고, 호출하려면 리소스에 Cognitive Services User 역할이 있어야 합니다 (1절 참조).

    ★ begin_ 과 폴링이 핵심입니다

    단계 의미
    begin_... 작업을 제출만 합니다. 결과가 바로 안 옵니다
    poller.result() 끝날 때까지 기다립니다 (SDK가 폴링을 대신해 줍니다)

    왜 비동기인가요

    문서 분석은 시간이 걸립니다. Lab 14의 비디오 생성과 같은 이유입니다. 오래 걸리는 작업은 제출 → 폴링 패턴을 씁니다.

    시험에 "문서 분석 결과를 어떻게 받는가?" → 작업을 제출하고 완료를 기다린다(폴링) 로 나옵니다. REST 는 작업 URL 을 직접 폴링하고, SDK 는 poller 가 대신해 줍니다.

    6. ✅ 체크포인트

    여기까지 됐으면 통과입니다

    • [ ] 분석기를 만들고 필드 3개를 정의했다
    • [ ] 영수증에서 필드별 값이 추출됐다
    • [ ] OCR과 CU의 차이를 한 문장으로 말할 수 있다
    • [ ] begin_... → poller.result() 구조를 안다

    🔧 안 될 때

    분석을 실행하면 권한 오류(403)가 납니다

    Cognitive Services User 역할이 없는 경우입니다 (1절 참조). Contributor 만으로는 안 됩니다. 손을 드세요 — 강사가 역할을 부여합니다.

    Content Understanding 메뉴가 안 보입니다

    프로젝트의 도구·지식(Tools) 안에 있습니다. 포털 구성이 자주 바뀌니 검색창에 Content Understanding 을 입력해 보세요.

    리전에 따라 제공되지 않을 수도 있습니다. 안 보이면 손을 드세요 — 강사 화면으로 대체합니다. 시험 포인트는 전부 전달됩니다.

    필드 값이 비어 있습니다
    • 이미지가 흐리거나 글자가 작으면 인식률이 떨어집니다. 더 선명한 걸로 바꿔 보세요
    • 필드 설명을 구체적으로 적으세요 — "합계, 총액, Total 로 표시된 금액"
    • 영수증에 그 항목이 실제로 있는지 확인하세요
    날짜 형식이 이상하게 나옵니다

    필드 유형을 날짜로 지정했는지 확인하세요. 문자열로 두면 영수증에 적힌 그대로 나옵니다.

    금액에 쉼표가 들어가 문자열로 나옵니다

    필드 유형을 숫자로 지정하세요. 그래도 안 되면 설명에 "쉼표 없는 숫자로" 를 추가해 보세요.

    💡 두 강의가 여기서 만납니다

    5강에서 "필드 매핑 5단계"를 개념으로 배웠고, 11강과 이 실습에서 그걸 실제로 만들었습니다.

    영수증 → 스키마 정의 → 추출 → 시스템에 바로 넣을 수 있는 JSON. 이게 "정보 추출" 워크로드의 실체입니다.
