    Lab 03 — 모델 배포 제대로 하기

    이 실습에서 하는 것

    어제는 "연결 확인용"으로 아무 생각 없이 배포했습니다. 오늘은 배포할 때 정하는 네 가지를 하나씩 보면서 왜 그 값인지 이해합니다.

    선행 Lab 02 완료 · 예상 시간 35분 · 비용 0원 (설정만 봅니다)

    0. 어제 만든 배포를 다시 엽니다

    새로 만들지 않습니다. 어제 배포한 gpt-5.4-mini 의 설정을 열어 하나씩 확인합니다.

    1. ai.azure.com → 내 프로젝트 → 배포(Deployments)
    2. gpt-5.4-mini 클릭
    3. 편집 또는 설정 화면을 엽니다

    배포할 때 정하는 네 가지

    무엇 어디서 다루나
    1 배포 유형 1절
    2 모델 버전 2절
    3 속도 제한 (TPM) 3절
    4 가드레일 (컨텐츠 필터) 4절

    ★ 이 네 가지가 시험에 그대로 나옵니다.

    1. 배포 유형 (8분)

    종량제 (Pay-as-you-go) 확보형 (Provisioned / PTU)
    결제 쓴 만큼 확보한 만큼 (안 써도 과금)
    성능 공유 — 몰리면 느려질 수 있음 보장됨
    적합 요청량이 불규칙할 때 일정 성능을 보장해야 할 때

    종량제 안에도 갈래가 있습니다 — 어제 겪은 그것

    Standard (지역) Global Standard
    처리 위치 내 지역 안에서 전 세계로 분산
    할당량 지역별로 따로 훨씬 넉넉
    적합 데이터 소재지 규제가 있을 때 일반적인 경우

    어제 Global Standard 를 고른 이유가 이겁니다

    할당량 자체가 다릅니다. gpt-5.4-mini 는 신규 구독 기준으로 Global Standard 에만 할당량이 있습니다 — 1,000K TPM 입니다. 지역형 Standard 는 기본 할당량이 없어서 고르면 배포가 실패합니다.

    32명 × 10K = 320K 이므로 Global Standard 로 3배 여유가 생깁니다.

    ★ 시험 포인트 — 세 단계를 구분하세요

    배포 유형 처리 범위 이런 조건일 때
    Standard (지역) 내가 고른 단일 리전 안 "데이터가 특정 국가 안에서"
    DataZone 여러 국가를 묶은 권역 (EU / US 등) "데이터가 EU 안에서"
    Global Standard 전 세계로 분산 소재지 제약이 없을 때 (기본)

    DataZone 을 "한 국가"로 외우면 틀립니다. EU 데이터 존은 여러 유럽 국가를 포함합니다. "한 국가 안"이 조건이면 지역형 Standard 입니다.

    확인해 보세요

    배포 화면에서 현재 유형이 무엇으로 되어 있는지 봅니다. 어제 만든 건 Global Standard 입니다.

    우리는 왜 종량제인가요

    수업에서는 하루에 몇 번만 호출합니다. 확보형으로 잡으면 수업하지 않는 밤새도록 과금됩니다. 크레딧이 하루 만에 사라집니다.

    ★ 시험에 이렇게 나옵니다

    "사내 챗봇을 배포했는데 요청량이 시간대별로 들쭉날쭉하고 야간에는 호출이 거의 없다. 비용 측면에서 가장 적합한 배포 유형은?"

    → 종량제. "요청량이 불규칙하다"가 나오면 종량제입니다. 반대로 "일정 성능을 보장해야 한다"가 나오면 확보형입니다.

    2. 모델 버전 (5분)

    배포 화면에서 버전과 업데이트 정책을 확인합니다.

    선택 의미 언제
    버전 고정 모델이 바뀌지 않음 프로덕션 — 동작이 바뀌면 안 될 때
    자동 업데이트 최신 개선을 자동 반영 개발·실험

    ★ 버전을 고정해도 답이 똑같이 나오지는 않습니다

    헷갈리기 쉬운 지점입니다. 둘은 다른 이야기입니다.

    버전 고정이 보장하는 것 보장하지 않는 것
    무엇 모델 자체가 안 바뀜 매번 같은 문장
    왜 어느 날 갑자기 성격이 변하지 않음 생성은 확률적 샘플링이기 때문

    같은 질문을 두 번 해도 답이 다를 수 있습니다. Lab 06에서 직접 확인합니다. 출력을 최대한 안정시키려면 temperature=0 을 씁니다 — 그래도 완전히 같다는 보장은 없습니다.

    정리하면 — 버전 고정은 "모델"을 고정하고, temperature=0 은 "출력"을 안정시킵니다.

    모델은 언젠가 종료됩니다 (retire)

    오래된 버전은 Microsoft가 공지 후 서비스를 종료합니다. 버전을 고정했다면 종료 공지를 챙겨 봐야 합니다. 안 그러면 어느 날 갑자기 멈춥니다.

    3. 속도 제한 — TPM (10분)

    TPM = Tokens Per Minute, 분당 처리 가능한 토큰 수입니다.

    알아야 할 것 설명
    무엇을 세나 입력 + 출력 토큰, 분당 기준
    높이면 동시에 더 많은 요청을 받을 수 있습니다
    어디서 빠지나 구독 전체 할당량에서 차감 — 모델·리전별 총량을 여러 배포가 나눠 씁니다

    TPM 은 응답의 total_tokens 를 더한 값이 아닙니다

    Lab 04에서 본 usage.total_tokens 는 그 호출이 실제로 쓴 양입니다. TPM 은 속도 제한이라서, 서비스가 요청을 받을 때 미리 추정해서 깎습니다.

    usage.total_tokens TPM 차감
    시점 응답이 온 뒤 요청을 받을 때
    값 실제 사용량 추정값 (요청 크기 + 요청한 최대 출력 길이)

    그래서 출력이 짧게 끝나도 큰 max_output_tokens 를 요청했다면 그만큼 한도를 쓴 것으로 계산될 수 있습니다. "실제로 조금 썼는데 왜 429?" 의 답이 이것입니다.

    해보세요

    1. 배포 설정에서 TPM 값을 확인합니다
    2. 값을 조금 올려 봅니다 (예: 10K → 20K)
    3. 저장합니다

    어제 429 오류가 났던 분

    같은 교실에서 동시에 요청이 몰리면 TPM 한도에 걸립니다. 여기서 올려두면 오늘 실습이 편해집니다.

    ★ 시험에 이렇게 나옵니다

    "429 Too Many Requests 오류가 반복된다. 무엇을 조정해야 하는가?"

    → TPM 할당량. 키나 엔드포인트 문제가 아닙니다.

    실무에서는 429 의 원인이 여러 개입니다

    시험 답은 TPM 이지만, 실제로 429 가 나는 이유는 이렇게 나뉩니다.

    원인 증상 대응
    TPM 한도 긴 프롬프트를 몰아 보낼 때 할당량 올리기 · 프롬프트 줄이기
    RPM(분당 요청 수) 한도 짧은 요청을 아주 자주 보낼 때 호출 간격 두기
    구독 전체 할당량 소진 다른 사람 배포가 다 써버림 배포별 TPM 나누기
    일시적 혼잡 특정 시간대에만 재시도 (SDK가 자동으로 함)

    openai SDK 는 429 를 자동으로 두 번 재시도합니다. 그래도 실패했다면 일시적 혼잡이 아니라 한도 문제로 보는 게 맞습니다.

    4. 가드레일 — 컨텐츠 필터 (10분)

    모델이 유해한 내용을 받지도, 내보내지도 않게 막는 장치입니다.

    네 가지 범주

    범주 무엇을 막나
    증오 · 공정성 특정 집단을 겨냥한 차별적 표현
    성적 콘텐츠 부적절한 성적 표현
    폭력 폭력·상해를 조장하는 내용
    자해 자해를 조장하거나 방법을 알려주는 내용

    각 범주마다 심각도 단계를 조절할 수 있습니다.

    가장 중요한 것 — 입력과 출력에 따로 적용됩니다

    사용자 입력 ──[입력 필터]──> 모델 ──[출력 필터]──> 사용자에게

    ★ 시험에 이렇게 나옵니다

    "입력은 통과했는데 출력이 차단됐다. 어느 설정을 조정해야 하는가?"

    → 출력 필터. 둘이 따로 설정된다는 걸 알아야 풀립니다.

    확인해 보세요

    1. 배포 설정에서 컨텐츠 필터 항목을 찾습니다
    2. 현재 적용된 필터를 열어 네 범주와 심각도를 눈으로 확인합니다
    3. 입력(프롬프트) 과 출력(완성) 이 나뉘어 있는지 봅니다

    필터를 끄지 마세요

    학생 구독에서는 보통 기본 필터가 고정되어 있습니다. 바꿀 수 있더라도 수업 중에는 기본값 그대로 두세요.

    5. ✅ 체크포인트

    여기까지 됐으면 통과입니다

    • [ ] 내 배포의 배포 유형이 무엇인지 말할 수 있다
    • [ ] 버전 고정 vs 자동 업데이트의 차이를 말할 수 있다
    • [ ] TPM 값을 확인했고, 그것이 속도 제한(실사용량 합계가 아님)이라는 걸 안다
    • [ ] 컨텐츠 필터 4범주를 찾았고, 입력과 출력이 따로라는 걸 확인했다

    설정 화면을 캡처해 두면 오늘 저녁 복습에 좋습니다.

    🔧 안 될 때

    배포 설정에서 TPM을 바꿀 수 없습니다

    학생 구독은 할당량 상한이 낮게 묶여 있을 수 있습니다.

    • 현재 값만 확인하고 넘어가세요. 실습에는 지장 없습니다
    • 오늘 429가 반복되면 손을 드세요
    컨텐츠 필터 항목이 안 보입니다

    배포 상세 화면 또는 프로젝트의 안전성(Safety) 메뉴에 있습니다. 포털 구성이 자주 바뀌니 메뉴 이름으로 검색해 보세요. 못 찾으면 손을 드세요.

    설정을 바꿨더니 배포가 “업데이트 중”에서 멈춰 있습니다

    1~2분 걸립니다. 새로고침해 보세요. 5분 넘게 멈춰 있으면 손을 드세요.

    💡 오늘 기억할 한 줄

    배포할 때 정하는 네 가지 — 배포 유형 · 버전 · TPM · 가드레일. 시험에서 "배포 시 고려할 사항"을 물으면 이 네 개입니다.
