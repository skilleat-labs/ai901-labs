    Lab 02 — 키·Python 환경·첫 연결

    이 실습에서 하는 것

    모델을 하나 배포하고, 내 노트북에서 코드로 불러서 답을 받습니다. 1일차의 마지막이자 가장 중요한 실습입니다.

    선행 Lab 01 완료 · Python 3.10 이상 (설치 방법 · Lab 00 4절에서 확인) · 예상 시간 45분 · 비용 약 $0.01 미만

    이게 안 되면 2~4일차가 전부 막힙니다

    오늘 남은 시간은 이 실습에 다 쓰셔도 됩니다. 혼자 10분 이상 붙잡지 말고 손을 드세요.

    1. 모델 하나 배포하기 (5분)

    코드로 부르려면 부를 대상이 있어야 합니다. 지금은 가장 작은 모델 하나만 올립니다.

    1. ai.azure.com → 내 프로젝트 → 모델 카탈로그

    2. gpt-5.4-mini 를 검색해서 선택합니다.

    3. 배포 를 누릅니다. 두 갈래가 나옵니다.

      고를 것 설명
      기본 설정 전역 표준과 기본 할당량으로 설정합니다 ❌
      사용자 지정 설정 나만의 SKU, 할당량, PTU, 스필오버, 가드레일을 설정합니다 ✅

      반드시 사용자 지정 설정 을 고르세요

      «기본 설정» 을 누르면 할당량을 기본값 그대로 크게 잡습니다. TPM 은 구독 전체에서 나눠 쓰는 자원이라, 앞 몇 명이 크게 잡으면 뒷사람이 "할당량 부족" 으로 배포를 못 합니다.

      우리는 TPM 을 직접 낮춰야 하므로 «사용자 지정 설정» 으로 들어갑니다.

    4. 배포 유형이 글로벌 표준(Global Standard) 인지 확인합니다.

      그 아래 우선 처리는 사용 안 함 그대로, 가드레일은 DefaultV2 그대로 둡니다. (가드레일이 무엇인지는 내일 Lab 03 에서 다룹니다)

      ⚠ Standard 가 아니라 Global Standard 입니다

      둘은 처리 위치와 할당량 규모가 다릅니다. gpt-5.4-mini 는 지역형 Standard 에 기본 할당량이 아예 없어서 그걸 고르면 배포가 실패합니다. 이유는 내일 Lab 03 에서 다룹니다.

    5. 배포 이름을 확인합니다. 기본값 gpt-5.4-mini 를 그대로 쓰세요.

    6. 「분당 토큰 속도 제한」 칸에 10000 을 입력합니다.

      이 칸은 “K” 단위가 아니라 실제 토큰 수 입니다

      분당 토큰 속도 제한   [ 10000 ]  / 1000000
                       ↑ 내가 쓸 값   ↑ 구독 전체 한도

      10000 을 그대로 입력하세요. 10 이나 10K 가 아닙니다. 오른쪽 1000000 은 구독 전체가 나눠 쓰는 총량입니다.

      슬라이더 최저값(1000)으로 두지 마세요

      너무 작으면 호출 한 번에 한도를 넘어 429 가 쏟아집니다.

      특히 Lab 05(대화를 기억하는 챗봇)에서 터집니다. 대화가 쌓이면 매 호출마다 지금까지의 전체 대화를 다시 보내기 때문에, 10턴째에는 한 번에 3~5천 토큰이 들어갑니다. 1,000 으로 두면 한 번도 못 부릅니다.

      1,000 10,000
      분당 호출 1~2회 10~14회
      Lab 05 ❌ 막힘 ✅

      반대로 크게 잡아도 안 됩니다 — 뒷사람이 막힙니다

      TPM 은 구독 전체에서 나눠 쓰는 자원입니다. 앞 몇 명이 크게 잡으면 나머지가 "할당량 부족" 으로 배포를 못 합니다.

      32명 × 10,000 = 320,000 으로 구독 한도(1,000,000)의 32% 만 씁니다. 강사 데모와 이미지 모델 몫까지 남습니다. (강사가 다른 값을 안내하면 그 값을 쓰세요)

    7. 배포 → 완료될 때까지 기다립니다 (1~2분).

    배포 이름을 꼭 메모하세요

    코드에서 쓰는 건 모델 이름이 아니라 배포 이름입니다. 기본값을 바꾸지 않았다면 gpt-5.4-mini 입니다. 오타 하나로 404가 납니다.

    왜 작은 모델인가요

    지금은 "연결이 되는가"만 확인하면 되기 때문입니다. 작고 싸고 빠릅니다. 어떤 모델을 왜 고르는지, 배포 유형·TPM·컨텐츠 필터는 무엇인지는 내일(2일차) Lab 03에서 제대로 다룹니다.

    2. 엔드포인트와 키 복사 (5분)

    1. 프로젝트 홈 화면에서 개요 를 봅니다.

    2. 두 가지를 복사해서 메모장에 붙여 둡니다.

      무엇 생김새
      엔드포인트 모델을 부르는 주소 https://<리소스이름>.openai.azure.com/openai/v1/
      API 키 그 요청을 인증하는 수단 길고 무작위한 문자열 (Key 1 / Key 2)

    ★ 엔드포인트는 두 개가 있습니다 — 헷갈리면 연결이 안 됩니다

    Foundry 프로젝트 홈 화면에 주소가 두 개 나란히 보입니다.

    화면의 이름 생김새 쓰는 곳
    프로젝트 엔드포인트 ...services.ai.azure.com/api/projects/... 에이전트 (Lab 09)
    Azure OpenAI 엔드포인트 ...openai.azure.com/openai/v1 모델 — 오늘 쓸 것

    우리가 쓸 건 오른쪽, openai.azure.com 으로 된 것입니다. services.ai.azure.com 을 넣으면 연결되지 않습니다.

    그리고 주소 끝의 /openai/v1 이 반드시 있어야 합니다. 없으면 404 입니다.

    키는 비밀번호입니다

    • 화면 공유 중이라면 키가 보이지 않게 가리세요
    • 코드에 직접 적지 않습니다. 다음 단계에서 .env 파일에 넣습니다
    • GitHub에 올리지 마세요

    키가 왜 두 개(Key 1, Key 2)인가요

    서비스를 멈추지 않고 키를 교체하기 위해서입니다. Key 1을 쓰는 중에 Key 2를 새로 발급해 바꿔 끼우는 식입니다. 아무거나 하나 쓰면 됩니다.

    3. Python 환경 만들기 (12분)

    Python 설치가 안 된 분 — 먼저 읽으세요

    포털의 웹 VS Code 로 대신할 수 있습니다. 설치가 전혀 필요 없습니다.

    모델 화면 → 「코드에서 계속」 → 맨 아래 「웹용 VS Code 설치 건너뛰기」

    Azure Cloud Shell 기반이라 진짜 리눅스 터미널이 열립니다. 3절부터 5절까지를 그 안에서 그대로 하시면 됩니다 — mkdir · .env 만들기 · pip install · python verify.py 전부 됩니다.

    가상 환경(python -m venv)은 건너뛰어도 됩니다. 이미 격리된 공간입니다.

    주의 두 가지 — 그래서 비상용입니다
    시간 제한 화면 아래에 남은 시간이 표시됩니다 (약 4시간). 끊기면 다시 열어야 합니다
    파일 보존 샌드박스가 초기화되면 만든 파일이 사라질 수 있습니다

    4일 동안 같은 ai901/ 폴더를 Lab 16 까지 이어서 씁니다. 매일 처음부터 다시 만들게 되면 시간이 많이 듭니다.

    코드는 따로 백업해 두세요. 퇴실 전에 내 PC 로 내려받거나 메일로 보내두면 됩니다.

    대신 좋은 점

    이미 로그인된 상태라 3일차 Lab 09 의 az login 이 필요 없습니다.

    되도록 로컬에 설치하세요

    가상 환경과 .env 는 시험에 나오는 개념입니다. 오늘 막히지 않는 것이 우선이니 비상 경로로 쓰시고, 저녁에 로컬에 설치해서 다시 해보시길 권합니다.

    작업할 폴더를 하나 만들고, 그 안에 가상 환경을 만듭니다.

    mkdir ai901
cd ai901
python -m venv .venv
.venv\Scripts\activate

    mkdir ai901
cd ai901
python -m venv .venv
source .venv/bin/activate

    터미널 프롬프트 앞에 (.venv) 가 붙으면 활성화된 것입니다.

    (.venv) C:\Users\hong\ai901>

    이제 패키지를 설치합니다. 같은 폴더에 requirements.txt 를 만들고 아래를 넣으세요.

    requirements.txt
    openai==2.46.0
python-dotenv==1.2.4

    pip install -r requirements.txt

    설치 확인:

    pip list

    목록에 openai 2.46.0 과 python-dotenv 가 보이면 됩니다.

    ★ 버전을 고정하는 이유 — 꼭 == 로 설치하세요

    pip install openai 로 설치하면 그날의 최신 버전이 들어옵니다. SDK가 올라가면서 메서드 이름이나 인자가 바뀌는 일이 실제로 있어서, 어제까지 되던 코드가 오늘 안 되는 상황이 생깁니다.

    교실에서는 이게 더 심각합니다. 설치 시점이 조금씩 달라서 32명의 환경이 서로 달라지면 오류를 같이 잡을 수 없습니다.

    openai 2.46.0 과 azure-identity 1.25.3 은 Microsoft 공식 문서가 함께 테스트했다고 밝힌 조합입니다. 그래서 이 버전으로 맞춥니다.

    가상 환경이 왜 필요한가요

    프로젝트마다 쓰는 패키지 버전이 다르기 때문입니다. 가상 환경 없이 설치하면 다른 프로젝트와 충돌합니다. 실무에서는 거의 항상 씁니다.

    4. .env 파일 만들기 (8분)

    ai901 폴더 안에 .env 라는 이름의 파일을 만듭니다. (확장자 없이 점으로 시작합니다)

    AZURE_OPENAI_ENDPOINT=https://<리소스이름>.openai.azure.com/openai/v1/
API_KEY=여기에_키_붙여넣기
MODEL_DEPLOYMENT_NAME=gpt-5.4-mini

    지름길 — 포털이 코드를 통째로 줍니다

    모델 화면 우상단 「코드에서 계속」 을 누르면 엔드포인트 · API 키 · 동작하는 예제 코드가 한 화면에 나옵니다.

    • 인증 방법 드롭다운을 API key 로 바꾸세요 (기본값은 Entra ID 입니다)
    • 거기 나온 주소는 ...services.ai.azure.com/openai/v1 일 수 있습니다. 홈 화면의 ...openai.azure.com/openai/v1 과 호스트가 다른데 둘 다 됩니다. 헷갈리면 한쪽만 골라서 끝까지 그걸 쓰세요.

    아래 절차는 홈 화면에서 직접 가져오는 방법입니다. 둘 중 편한 쪽으로 하세요.

    엔드포인트 가져오기

    1. ai.azure.com → 내 프로젝트 홈 화면
    2. 가운데 가로로 긴 칸에서 Azure OpenAI 엔드포인트 를 찾습니다
    3. 오른쪽 복사 아이콘을 눌러 복사합니다
    https://ai901-01-nrkim.openai.azure.com/openai/v1
                                        └────────┘ 이 경로가 있어야 합니다

    복사한 뒤 끝을 한 번 보세요 — / 를 붙입니다

    포털은 끝에 슬래시 없이 /openai/v1 까지만 줍니다. .env 에는 끝에 / 를 붙여서 넣으세요.

    AZURE_OPENAI_ENDPOINT=https://ai901-01-nrkim.openai.azure.com/openai/v1/

    완성한 값을 환경 기록표에 적어 두세요.

    왼쪽의 프로젝트 엔드포인트를 넣으면 안 되나요

    안 됩니다. 그건 에이전트를 부를 때 쓰는 주소라서 Lab 09에서 따로 씁니다. services.ai.azure.com 이 보이면 잘못 가져온 것입니다.

    화면에 /openai/v1 이 안 보이고 주소가 짧게 끝납니다

    Azure 포털의 키 및 엔드포인트 화면은 호스트까지만 보여주기도 합니다. 그럴 땐 직접 이어 붙이세요.

    https://<리소스이름>.openai.azure.com  +  /openai/v1/

    <리소스이름> 은 Lab 01에서 정한 이름입니다. .cognitiveservices.azure.com 주소가 보이더라도, 이 과정에서는 .openai.azure.com 쪽을 쓰세요.

    자주 틀리는 네 가지

    • 프로젝트 엔드포인트를 넣음 · /openai/v1/ 를 빠뜨림 ← 가장 흔합니다
    • 따옴표를 넣지 마세요. API_KEY="abc" ❌ → API_KEY=abc ✅
    • 등호 앞뒤에 공백을 넣지 마세요. API_KEY = abc ❌
    • 줄 끝 공백도 오류가 됩니다. 붙여넣고 끝에 커서를 둬서 확인하세요

    VS Code에서 파일 이름이 .env.txt 로 저장될 때

    저장할 때 파일 형식을 모든 파일(All Files) 로 바꾸고 .env 로 저장하세요. 탐색기에서 파일 확장명 표시를 켜두면 확인하기 쉽습니다.

    5. verify.py 실행하기 (15분)

    같은 폴더에 verify.py 를 만들고 아래를 넣습니다.

    import os
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()
client = OpenAI(
    base_url=os.getenv("AZURE_OPENAI_ENDPOINT"),
    api_key=os.getenv("API_KEY"))

r = client.responses.create(
    model=os.getenv("MODEL_DEPLOYMENT_NAME"),
    input="안녕하세요. 한 문장으로 인사해 주세요.")
print(r.output_text)

    실행합니다.

    python verify.py

    코드가 하는 일

    줄 하는 일
    load_dotenv() .env 를 읽어 환경 변수로 올립니다
    client = OpenAI(...) 연결을 만드는 줄 — 아직 아무것도 보내지 않습니다
    client.responses.create(...) 실제로 요청을 보내는 줄
    print(r.output_text) 모델의 답을 출력합니다

    ★ 이 구분이 시험에 나옵니다

    "이 코드에서 프롬프트를 제출하는 줄은?" 이라는 문제가 실제로 출제됩니다. 답은 client.responses.create(...) 입니다. OpenAI(...) 는 연결만 만듭니다.

    6. ✅ 체크포인트

    여기까지 됐으면 1일차 완료입니다

    • [ ] 터미널 프롬프트에 (.venv) 가 보인다
    • [ ] pip list 의 openai 가 2.46.0 이다
    • [ ] .env 에 엔드포인트 · 키 · 배포 이름 세 줄이 들어 있다
    • [ ] 엔드포인트가 /openai/v1/ 로 끝난다 ← 404의 1순위 원인
    • [ ] 엔드포인트를 환경 기록표에 적었다
    • [ ] python verify.py 를 실행했다
    • [ ] 터미널에 모델의 인사말이 한 줄 출력됐다 ← 이게 성공 기준입니다

    전원이 통과해야 1일차가 끝납니다. 먼저 끝나신 분은 옆자리를 도와주세요.

    🔧 안 될 때

    오류 메시지의 숫자를 먼저 보세요

    401 · 404 · 429 중 어느 것인지에 따라 원인이 완전히 다릅니다.

    401 Unauthorized — 인증 실패

    키가 잘못 전달된 것입니다.

    1. .env 의 API_KEY 값 앞뒤에 공백이나 따옴표가 없는지 확인
    2. 포털에서 키를 다시 복사해서 붙여넣기
    3. Key 1 대신 Key 2로 바꿔 시도
    404 Not Found — 주소나 배포 이름을 못 찾음

    가장 흔한 오류입니다. 원인이 세 가지인데, 반드시 이 순서로 확인하세요.

    ① 주소 경로 — 이게 제일 흔합니다

    .env 의 AZURE_OPENAI_ENDPOINT 가 /openai/v1/ 로 끝나는지 보세요.

    https://ai901-01-nrk.openai.azure.com/            ❌ 404
https://ai901-01-nrk.openai.azure.com/openai/v1   ❌ 끝 슬래시 없음
https://ai901-01-nrk.openai.azure.com/openai/v1/  ✅

    ② 배포 이름

    1. Foundry 포털 → 배포 목록에서 이름을 그대로 복사
    2. .env 의 MODEL_DEPLOYMENT_NAME 과 글자 하나까지 같은지 확인
    3. 모델 이름이 아니라 배포 이름을 넣었는지 확인 (배포할 때 이름을 바꿨다면 그 이름입니다. 기본값을 그대로 뒀다면 둘이 같습니다)

    ③ 모델이 그 기능을 지원하는지

    배포한 모델이 responses 를 지원하지 않으면 404 또는 매개변수 오류가 납니다. 이 과정은 gpt-5.4-mini 기준입니다. 다른 모델을 배포했다면 손을 드세요.

    어디까지 왔는지 확인하는 법

    401 이 난다면 주소는 맞은 것입니다 (서버에 닿아서 인증까지 갔다는 뜻). 404 는 아직 주소나 배포를 못 찾은 단계입니다.

    429 Too Many Requests — 속도 제한

    같은 교실에서 동시에 요청이 몰렸을 수 있습니다.

    1. 30초 뒤 다시 실행
    2. 계속 나면 포털에서 배포의 TPM(분당 토큰) 할당량을 올립니다
    3. TPM은 내일 Lab 03에서 제대로 다룹니다
    ModuleNotFoundError: No module named 'openai'

    가상 환경이 꺼져 있습니다.

    1. 터미널 프롬프트 앞에 (.venv) 가 있는지 확인
    2. 없으면 3번 단계의 활성화 명령을 다시 실행
    3. 그다음 pip install -r requirements.txt 재실행

    터미널을 새로 열면 가상 환경이 꺼집니다

    매번 활성화해 줘야 합니다. 4일 내내 이 오류가 제일 많이 납니다.

    엔드포인트에 services.ai.azure.com 이 들어 있습니다

    프로젝트 엔드포인트를 잘못 가져온 것입니다. 가장 흔한 혼동입니다.

    프로젝트 홈 화면에서 Azure OpenAI 엔드포인트 칸(오른쪽)을 다시 복사하세요. openai.azure.com 이 들어 있어야 맞습니다.

    엔드포인트 주소에 cognitiveservices.azure.com 이 들어 있습니다

    Azure 포털의 키 및 엔드포인트 화면이 그 주소를 보여줬을 수 있습니다.

    이 과정에서는 https://<리소스이름>.openai.azure.com/openai/v1/ 를 쓰세요. <리소스이름> 은 Lab 01에서 정한 Foundry 리소스 이름입니다.

    openai 버전이 2.46.0 이 아닙니다 
    pip install -r requirements.txt --force-reinstall

    requirements.txt 에 openai==2.46.0 이 == 로 적혀 있는지 확인하세요. 버전이 다르면 responses.create 의 동작이 달라질 수 있습니다.

    엔드포인트나 키가 None 이라고 나옵니다

    .env 를 못 읽고 있습니다.

    1. .env 가 verify.py 와 같은 폴더에 있는지 확인
    2. 파일 이름이 .env.txt 로 저장되지 않았는지 확인
    3. 터미널의 현재 위치가 그 폴더인지 확인 (cd ai901)
    4. load_dotenv() 가 os.getenv() 보다 위에 있는지 확인
    배포 화면에 TPM(할당량) 칸이 안 보입니다

    «기본 설정» 으로 들어간 것입니다. 거기서는 할당량을 바꿀 수 없습니다.

    1. 취소하고 배포 를 다시 누르세요
    2. «사용자 지정 설정» 을 고르세요
    3. 이미 기본 설정으로 배포했다면 — 배포 목록에서 그 배포를 열어 편집으로 TPM 을 10K 로 낮추면 됩니다. 지우고 다시 만들지 않아도 됩니다

    python 명령을 찾을 수 없습니다
