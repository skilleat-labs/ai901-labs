# Lab 12 — Voice Live 실시간 음성 (강사 데모)

!!! warning "이 랩은 보는 실습입니다"

## 0. 왜 직접 안 하나요

Voice Live는 **연결을 열어둔 시간만큼 과금**됩니다.
Lab 11의 STT·TTS와 과금 방식 자체가 다릅니다.

| | 과금 기준 |
|---|---|
| Lab 11 STT · TTS | **처리한 분량** (글자 수 · 오디오 길이) — 월 무료 한도 있음 |
| **Voice Live** | **연결을 유지한 시간** — 말하지 않아도 과금 |

20명이 15분씩 연결을 열면 이 과정에서 **가장 비싼 구간**이 됩니다.
그리고 깜빡 닫지 않으면 그대로 계속 돌아갑니다.

!!! note "★ 이 과금 방식 자체가 시험 포인트입니다"
    "실시간 음성 연결의 비용에서 주의할 점은?" → **열어둔 시간이 곧 비용**입니다.

---

## 1. 무엇이 다른가 (5분 · 설명)

지금까지는 이렇게 **순서대로** 했습니다.

```text
[음성] → STT → [글자] → 모델 → [글자] → TTS → [음성]
```

Voice Live는 이 과정을 **하나의 연결 안에서 동시에** 처리합니다.

```text
[음성] ←─────── 실시간 양방향 연결 ───────→ [음성]
```

| | 파이프라인 (Lab 11) | Voice Live |
|---|---|---|
| 단계 | STT → 모델 → TTS (각각 호출) | **하나의 연결** |
| 지연 | 단계마다 쌓임 | 훨씬 짧음 |
| 끼어들기 | 어려움 | **가능** (말 중간에 끊을 수 있음) |
| 비용 | 처리량 기준 | **연결 시간** 기준 |

!!! question "그럼 항상 Voice Live를 쓰면 되나요"
    아닙니다. **실시간 대화가 필요할 때만** 씁니다.
    녹음 파일을 나중에 받아적는 일이라면 파이프라인이 훨씬 쌉니다.

    **② 끼어들기**

    → 기록: ________________

    **③ 연결 상태 표시**
    화면 어디에서 "연결 중"을 알 수 있나요? 이게 왜 중요한가요?

    → 기록: ________________

## 3. 언제 쓰는가 (2분)

| 상황 | 선택 |
|---|---|
| 콜센터 실시간 응대 | **Voice Live** |
| 음성 비서 · 실시간 통역 | **Voice Live** |
| 녹음된 회의록 받아쓰기 | 파이프라인 (STT) |
| 안내 방송 음성 생성 | 파이프라인 (TTS) |
| 상담 녹취 1,000건 분석 | **일괄 처리(batch)** |

!!! danger "★ 시험 함정 — 긴 녹음에 실시간을 고르지 마세요"
    "지난 6개월 상담 녹취를 분석한다" 에 Voice Live나 `recognize_once` 를 고르면 오답입니다.
    → **일괄 처리(batch transcription)** 입니다.
