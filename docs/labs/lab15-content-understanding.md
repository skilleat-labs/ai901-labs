# Lab 15 — Content Understanding 으로 영수증 추출

!!! info "이 실습에서 하는 것"
    영수증 이미지에서 **총 금액 · 날짜 · 상호**를 각각의 **필드 값**으로 뽑습니다.
    글자를 읽는 게 아니라, **쓸 수 있는 데이터**로 만드는 겁니다.

**선행** [Lab 13](lab13-multimodal-image.md) 완료 · **예상 시간** 40분 · **비용** 약 $0.1 미만

---

## 0. OCR 과 무엇이 다른가 (5분)

!!! note "★★ 5강에서 배운 구분이 여기서 실물이 됩니다"
    | | OCR | Content Understanding |
    |---|---|---|
    | 결과 | **글자 뭉치** | **이름 붙은 필드 값** |
    | 예 | `"합계 23,000원 2026-03-10"` | `{"총금액": 23000, "날짜": "2026-03-10"}` |
    | 다음 단계 | 직접 파싱해야 함 | **바로 시스템에 넣을 수 있음** |

    **"필드로 받는다"** 가 나오면 Content Understanding 입니다.
    "글자를 읽는다"면 OCR입니다. 시험에 이 짝으로 나옵니다.

**Lab 13(멀티모달)과도 다릅니다.** 멀티모달 모델도 영수증을 읽고 설명할 수 있지만,
**매번 같은 형식으로 돌려준다는 보장이 없습니다.** CU는 스키마를 미리 정해서 형식을 고정합니다.

---

## 1. 준비 — 영수증 이미지 (3분)

영수증 사진을 하나 준비합니다.

- 지갑에 있는 실물 영수증을 찍어도 되고
- 없으면 **메모장에 영수증처럼 적어서 스크린샷**을 찍어도 됩니다

```text
스킬잇 카페
2026-03-10 14:32
아메리카노  2  9,000
카페라떼    1  5,500
---------------------
합계          14,500
```

파일명은 **`receipt.png`** 로 저장하세요.

---

## 2. 분석기(Analyzer) 만들기 (15분)

여기가 핵심입니다. **무엇을 뽑을지 미리 정의**합니다.

1. [ai.azure.com](https://ai.azure.com) → 내 프로젝트 → **도구·지식** → **Content Understanding**
2. 새 **분석기(Analyzer)** 를 만듭니다
3. 입력 유형을 **문서/이미지** 로 선택합니다

### 필드 스키마 정의

뽑을 필드를 하나씩 추가합니다.

| 필드 이름 | 유형 | 설명 |
|---|---|---|
| `상호` | 문자열 | 가게 이름 |
| `날짜` | 날짜 | 결제 일자 |
| `총금액` | 숫자 | 합계 금액 |

!!! tip "설명을 구체적으로 쓰세요"
    `총금액` 에 "합계, 총액, Total 로 표시된 최종 결제 금액" 처럼 적으면 정확도가 올라갑니다.
    **이게 프롬프트 역할을 합니다.**

### 테스트

4. `receipt.png` 를 업로드하고 **분석**을 실행합니다
5. 결과가 **필드별로** 나오는지 확인합니다

```json
{
  "상호":   "스킬잇 카페",
  "날짜":   "2026-03-10",
  "총금액": 14500
}
```

!!! success "이게 핵심입니다"
    OCR이었다면 `"스킬잇 카페 2026-03-10 14:32 아메리카노 2 9,000..."` 한 덩어리였을 겁니다.
    **이름이 붙은 값**으로 나왔다는 게 차이입니다.

## 3. 분석기 두 종류 (5분)

| | 미리 만들어진(prebuilt) 분석기 | 사용자 지정 분석기 |
|---|---|---|
| 준비 | 바로 씀 | **스키마를 직접 정의** ← 방금 한 것 |
| 대상 | 영수증·명함 등 일반 문서 | 우리 회사 양식 |
| 장점 | 빠름 | 원하는 필드만 정확히 |

!!! note "★ 시험 포인트"
    "사내 전용 양식에서 특정 필드를 뽑아야 한다" → **사용자 지정 분석기**
    "일반적인 영수증을 처리한다" → 미리 만들어진 분석기로 충분

## 4. 코드에서 부르는 구조 (10분)

!!! warning "오늘은 코드를 실행하지 않습니다"
    SDK 패키지와 메서드 이름이 버전에 따라 달라서, **구조만** 봅니다.
    시험이 묻는 것도 "흐름"이지 정확한 메서드명이 아닙니다.

```python
# extract.py — 구조
# 1. 클라이언트 생성
client = ContentUnderstandingClient(endpoint, credential)

# 2. 분석 작업 제출
operation = client.begin_analyze(
    analyzer_id="receipt-analyzer",
    document=file_bytes)

# 3. 완료까지 대기 (폴링)
result = operation.result()

# 4. 구조화된 결과 사용
print(result.fields["총금액"])
```

### ★ `begin_` 과 폴링이 핵심입니다

| 단계 | 의미 |
|---|---|
| `begin_analyze(...)` | **작업을 제출**만 합니다. 결과가 바로 안 옵니다 |
| `operation.result()` | **끝날 때까지 기다립니다** (폴링) |

!!! note "왜 비동기인가요"
    문서 분석은 시간이 걸립니다. Lab 14의 비디오 생성과 같은 이유입니다.
    **오래 걸리는 작업은 제출 → 폴링** 패턴을 씁니다.

    시험에 "문서 분석 결과를 어떻게 받는가?" → **작업 제출 후 폴링**으로 나옵니다.

## 🔧 안 될 때

??? failure "Content Understanding 메뉴가 안 보입니다"
    프로젝트의 **도구·지식(Tools)** 안에 있습니다.
    포털 구성이 자주 바뀌니 검색창에 `Content Understanding` 을 입력해 보세요.

    리전에 따라 제공되지 않을 수도 있습니다. 안 보이면 손을 드세요 —
    **강사 화면으로 대체**합니다. 시험 포인트는 전부 전달됩니다.

??? failure "필드 값이 비어 있습니다"
    - 이미지가 흐리거나 글자가 작으면 인식률이 떨어집니다. 더 선명한 걸로 바꿔 보세요
    - 필드 **설명**을 구체적으로 적으세요 — "합계, 총액, Total 로 표시된 금액"
    - 영수증에 그 항목이 실제로 있는지 확인하세요

??? failure "날짜 형식이 이상하게 나옵니다"
    필드 유형을 **날짜**로 지정했는지 확인하세요.
    문자열로 두면 영수증에 적힌 그대로 나옵니다.

??? failure "금액에 쉼표가 들어가 문자열로 나옵니다"
    필드 유형을 **숫자**로 지정하세요.
    그래도 안 되면 설명에 "쉼표 없는 숫자로" 를 추가해 보세요.
