# Lab 08 — 포털에서 에이전트 만들기

!!! info "이 실습에서 하는 것"
    어제 `chat3.py` 는 규정을 **프롬프트에 직접 붙였습니다.** 문서가 커지면 못 씁니다.
    오늘은 문서를 **업로드해서 붙이는** 에이전트를 만듭니다.

**선행** [Lab 07](lab07-system-grounding.md) 완료 · **예상 시간** 40분 · **비용** 약 $0.05 미만

---

## 0. 어제와 무엇이 다른가 (5분)

| | 어제 `chat3.py` | 오늘 에이전트 |
|---|---|---|
| 문서를 넣는 곳 | **프롬프트 안** | **업로드 → 지식(Knowledge)** |
| 문서 크기 | 토큰 한도까지만 | 수백 페이지도 가능 |
| 찾는 방식 | 전부 다 보냄 | **필요한 부분만 찾아서** 씀 |
| 할 수 있는 일 | 답하기 | 답하기 **+ 도구로 행동하기** |

!!! note "★ 에이전트 4요소 — 3강에서 배운 그대로입니다"
    | 요소 | 오늘 어디서 |
    |---|---|
    | **모델** | 1절에서 선택 |
    | **지침** (Instructions) | 1절에서 작성 |
    | **지식** (Knowledge) | 2절에서 파일 업로드 |
    | **도구** (Tools) | 3절에서 확인 |

---

## 1. 에이전트 만들기 (12분)

1. [ai.azure.com](https://ai.azure.com) → 내 프로젝트 → **에이전트(Agents)** → **새 에이전트**

2. 아래처럼 설정합니다.

    | 항목 | 값 |
    |---|---|
    | 모델 | `gpt-4o-mini` (Lab 02에서 배포한 것) |
    | 이름 | **`hr-agent`** ← 코드에서 쓰니 **정확히** 이대로 |

3. **지침(Instructions)** 에 아래를 붙여넣습니다.

    ```text
    너는 사내 인사 규정 도우미다.
    - 제공된 규정 문서와 인사 시스템 데이터만 근거로 답한다.
    - 휴가 신청은 잔여 연차를 먼저 확인한 뒤 진행한다.
    - 규정에 없는 내용은 '확인 필요'라고 답하고 임의로 처리하지 않는다.
    ```

4. 저장합니다.

!!! warning "이름을 꼭 `hr-agent` 로 하세요"
    Lab 09의 코드가 이 이름으로 에이전트를 찾습니다. 다르게 지으면 코드도 바꿔야 합니다.

!!! question "지침은 시스템 메시지와 같은 건가요"
    역할이 같습니다. 어제 `SYSTEM` 변수에 넣던 걸 **포털에 저장해 두는 것**입니다.
    코드에서 매번 보낼 필요가 없어집니다.

## 2. 지식 붙이기 — 파일 업로드 (15분)

### 먼저 규정 문서를 만듭니다

메모장이나 VS Code로 **`휴가규정.txt`** 를 만들고 아래를 넣어 저장하세요.

```text
[사내 휴가 규정]

제3조 (연차)
입사 1년 이상 직원은 연 15일의 연차를 부여한다.
입사 1년 미만 직원은 1개월 개근 시 1일의 연차를 부여한다.

제4조 (신청)
연차는 사용 3일 전까지 인사 시스템으로 신청한다.
3일 이내 긴급 신청은 팀장 승인을 받아야 한다.

제5조 (반차)
반차는 오전 09:00~13:00, 오후 13:00~18:00 중 선택한다.
반차 2회는 연차 1일로 계산한다.

제7조 (이월)
미사용 연차는 다음 해로 이월되지 않는다.
단, 회사 사정으로 사용하지 못한 경우 최대 5일까지 이월할 수 있다.
```

### 에이전트에 붙입니다

1. 에이전트 화면 → **지식(Knowledge)** 탭 → **추가**
2. **파일 검색(File search)** 을 선택합니다
3. `휴가규정.txt` 를 업로드합니다
4. **인덱싱이 끝날 때까지 기다립니다** (1~3분)

!!! note "지식 도구 세 가지 — 3강에서 배운 것"
    | 도구 | 무엇 |
    |---|---|
    | **파일 검색** | 업로드한 문서에서 찾습니다 ← 오늘 씁니다 |
    | 웹 검색 | 최신 정보를 가져옵니다 |
    | 데이터 원본 연결 | DB·API를 조회합니다 |

## 3. 플레이그라운드에서 테스트 (8분)

에이전트 화면의 **플레이그라운드** 또는 **테스트** 창에서 물어봅니다.

| 질문 | 기대하는 답 |
|---|---|
| `연차가 며칠인가요?` | 15일 + **제3조** 근거 |
| `반차 2번 쓰면 연차 며칠 쓴 건가요?` | 1일 + **제5조** |
| `미사용 연차는 이월되나요?` | 원칙적으로 안 됨, 예외 5일 + **제7조** |
| `병가는 며칠인가요?` | **확인 필요** (규정에 없음) |

!!! success "세 번째 질문이 핵심입니다"
    제7조는 **원칙과 예외가 같이** 있습니다. 에이전트가 둘 다 찾아서 답하면
    "문서에서 필요한 부분을 찾아 쓰고 있다"는 뜻입니다.

### 어제와 비교해 보세요

`chat3.py` 는 규정 전체를 매번 보냈습니다. 에이전트는 **질문에 관련된 부분만** 찾아 씁니다.
문서가 300페이지여도 같은 방식으로 동작합니다.

## 4. 도구(Tools) 둘러보기 (5분)

지금은 지식만 붙였지만, 에이전트는 **행동**도 할 수 있습니다.

| 도구 | 무엇 |
|---|---|
| 연결된 서비스 호출 | 외부 시스템의 기능을 부릅니다 |
| 코드 실행 | 계산·데이터 처리를 수행합니다 |
| 시스템 연동 | 업무 시스템에 **쓰기** 작업을 합니다 |

!!! danger "★ 쓰기 작업에는 승인이 필요합니다"
    "휴가를 신청해줘" 같은 요청은 **실제로 시스템을 바꿉니다.**
    그래서 에이전트가 도구를 쓰기 전에 **사람이 승인**하는 단계를 둡니다.

    2강에서 배운 **책임(Accountability)** 원칙이 여기서 구현됩니다.
    시험에 "에이전트가 외부 시스템을 변경하기 전에 필요한 것은?" → **사용자 승인**으로 나옵니다.

**지금은 도구 목록만 눈으로 확인하고 넘어갑니다.** 추가하지 마세요.

## 🔧 안 될 때

??? failure "에이전트 메뉴가 안 보입니다"
    프로젝트 안에 있어야 보입니다. 리소스 화면이 아니라 **프로젝트 홈**인지 확인하세요.
    포털 구성이 자주 바뀌니 검색창에 `agent` 를 입력해 보세요.

??? failure "파일 업로드 후 인덱싱이 끝나지 않습니다"
    - 3분 넘게 걸리면 새로고침해 보세요
    - 파일이 너무 크거나 형식이 안 맞을 수 있습니다. **`.txt` 로, 1KB 정도**면 충분합니다
    - 한글 파일명이 문제가 되면 `rules.txt` 로 바꿔 보세요

??? failure "근거 조항을 인용하지 않습니다"
    1. 지식이 **인덱싱 완료** 상태인지 확인
    2. 지침에 한 줄 추가: `"답변에 반드시 근거 조항을 '(제N조)' 형식으로 표시한다."`
    3. 저장 후 **새 대화**로 다시 시도 (기존 대화는 옛 지침을 쓸 수 있습니다)

??? failure "규정에 없는 것도 지어냅니다"
    지침을 강하게 바꿉니다.

    ```text
    규정 문서에 없는 내용은 반드시 '확인 필요'라고만 답한다. 추측하지 않는다.
    ```

??? failure "모델을 선택할 수 없습니다"
    Lab 02에서 배포한 모델이 **배포 완료** 상태인지 확인하세요.
    배포가 없으면 에이전트를 만들 수 없습니다.
